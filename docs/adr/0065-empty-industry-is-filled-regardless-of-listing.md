# 業種の空欄は上場区分によらず埋める（空の業種は「後に廃止した社」の印＝未来情報）

## Status

accepted（2026-10-03）。Issue [#797](https://github.com/kome-kome/financial_app/issues/797)
（[#784](https://github.com/kome-kome/financial_app/issues/784) の範囲外として切り出した残り）。

- #784（PR #796）の「上場区分が『上場』の社だけを埋める」を**置き換える**。JPX を上書きしない・
  許す業種名は DB に既にある名前だけ・会社の業種を空の財務行へ毎晩写す、は変えない。

## Context

業種（`companies.industry` / `financial_records.industry`）は JPX の上場会社一覧（東証のみ・今日の
一覧）から付けている。一覧に載らない社は業種が空のまま残る。#784 は EDINET コードリストの「提出者業種」
で、上場区分が「上場」の 108社（札証・福証の単独上場など）だけを埋めた。残る **587社**（非上場・区分空欄。
DB 上はすべて `is_active=False`）は「過去年度の分析が広く動く」として範囲から外し、影響を測ってから
決めることにした。

調べると、この空欄は単なる欠損ではなかった。**業種が空の社は「今日の JPX 一覧に載っていない＝その後に
上場廃止した社」とほぼ同じ集合**である。空文字は1つのグループとして扱われるので、過去の断面から見ると
「この先廃止される社」という**未来情報のラベル**になっていた。2019年度では通期行の 17%（657/3,788行）が
この1群に入っている。効いていた場所:

| 読み手 | 空の業種の扱い | 本番への経路 |
|---|---|---|
| VIEW `financial_metrics` の業種内Z（`z_roe_sec` / `z_op_margin_sec`・`PARTITION BY year, industry`） | 空文字が1つの業種として Z を作る | **M-2・M-6 の既定特徴量**（M-6 は毎晩の μ̂・`sell_ranking` の既定） |
| `macro_snapshots`（`fr.industry or companies.industry or "不明"`） | 「不明」という1カテゴリ | M-1 の R3 業種バケット・macro_gbdt の業種 target encoding・業種中立 rank-IC |
| `sector_gap_asof`（時点再現の gap・ADR-0057） | `_eligible_base` で落ちる | 評価専用のパネル（生存者バイアス） |
| 当日の sector_ols | `tradable_filters` で廃止社をそもそも読まない | **変わらない** |

## Decision

1. **業種の空欄は上場区分によらず、EDINET コードリストの提出者業種で埋める**。対象は提出者業種が
   33業種名（DB に既にある名前）に一致する 517社（非上場516・区分空欄1）。
2. **OOF の rank-IC の変化は採否の条件にしない**。空の業種は未来情報なので、埋めて rank-IC が下がったら
   「リークが抜けた」と読む（ADR-0055 決定7・`measure_split_bias_oof` と同じ考え方）。計測は影響の大きさの
   記録と、壊れていないかの確認に使う。止める条件は事前に固定した:
   - 当日 gap（夜間と同じ設定の sector_ols）がキー集合・値のどちらかで1件でも変わる
   - 母集団が縮む（gap パネルで gap を付けた後の行数が減る月・OOF の `n_oof_samples` の減少・
     前から業種があった社の行で業種内Z が非 NULL → NULL）
   - 業種名の種類が変わる
   - 模擬実行が壊れた（rollback が呼ばれた・ROLLBACK 後に空の件数が戻らない）
3. **33業種外の名前は書かず、上場区分で警告を分ける**。上場社なら WARNING（表記差か分類体系の変更の
   疑い）、非上場社なら INFO（`内国法人・組合（有価証券報告書等の提出義務者以外）` 69社・
   `外国法人・組合` 1社＝業種ではなく提出者の種別。毎晩70件の WARNING で本物の表記差を埋もれさせない）。
4. **選び方と書き込みを関数に分ける**（`_plan_industry_fill` / `_apply_industry_fill`）。計測が本番と
   同じ選び方で模擬補完するため。
5. **`PREPROCESS_VERSION` は上げない**。ADR-0039 が守るのは `factor_premia` の `mean_b` の単位
   （断面の winsorize→zscore）で、永続化される重みの7列＋momentum はどれも年度だけで区切る z（`yw`）で
   業種に依存しない。今回変わるのはデータ（どの業種に属するか）で、前処理の手続きではない。
6. **画面の同業比較は上場中の社だけを並べる**（`/api/companies?active_only=true`）。埋めると廃止社が
   古い財務のまま同業の順位に混ざる（サービス業 +91社・情報・通信業 +73社）。スクリーニングは変えない。

## 実測（2026-10-03・ローカル正本・書き込みなしの模擬実行）

`python -m scripts.measure_industry_fill_impact`（1つのトランザクションで補完前を測る → 本番と同じ関数で
補完を流す → 補完後を測る → ROLLBACK）。

**止める条件はどれにも当たらなかった。** 所要は前後あわせて約21分（gap パネル 約3分×2・OOF 約7分×2）。

| 項目 | 補完前 → 補完後 |
|---|---|
| 補完 | 会社 517社・財務行 3,954行（書かなかった: 33業種外 70社） |
| 業種が空（会社 / 財務行） | 587 / 4,324 → 70 / 370 → ROLLBACK 後 587 / 4,324（rollback の呼び出し 0回） |
| 業種名の種類 | 33 → 33 |
| 当日 gap（夜間と同じ設定） | 3,629行すべて完全一致・業種の α も不変 |

業種内Z（前から業種があった社の行。群の顔ぶれだけが変わる）:

| 列 | Spearman | \|差\| 中央値 / p90 / 最大 | 非 NULL→NULL |
|---|---|---|---|
| `z_roe_sec` | 0.9718（年度別 0.915〜1.000・最小は 2024） | 0.0084 / 0.080 / 10.26 | 0 |
| `z_op_margin_sec` | 0.9914（年度別 0.962〜1.000） | 0.0118 / 0.079 / 8.59 | 0 |

埋めた社の行は空の群から実業種の群へ移るので大きく動く（Spearman 0.588 / 0.757）。空のまま残る 70社の
行では各列1行が非 NULL→NULL になった（空の群が1社になる年）が、OOF の母集団には入っていなかった。

時点再現の gap パネル（63か月）: 母集団の減少率の中央値 1.48% → 1.41%、gap の付いた行 201,370 → 201,563
（+193）。共通行の gap は Spearman 0.9959・|差| 中央値 0.01pt・p90 3.3pt（最大 1,510pt は外れ値側）。

OOF（`run_comparison`・既定パラメータ・補完後 − 補完前・Bonferroni 3組で1検定あたり α=0.0167）:

| モデル | rank-IC | 業種中立 rank-IC | short_side_spread | `n_oof_samples` | 差の p |
|---|---|---|---|---|---|
| M-1 `macro_risk_return` | 0.1926 → 0.1926 | 0.1276 → 0.1273 | 0.0978 → 0.0978 | 54,910 → 54,910 | 全19期で差 0 |
| M-2 `macro_gbdt` | 0.1024 → 0.1046 | 0.0808 → 0.0837 | 0.0521 → 0.0540 | 27,328 → 27,328 | 0.59 |
| M-6 `macro_enet` | 0.1557 → 0.1560 | 0.1255 → 0.1258 | 0.0766 → 0.0759 | 27,328 → 27,328 | 0.28 |

- 「リークが抜けて rank-IC が下がる」可能性を見込んでいたが、**どのモデルでも有意な差は出なかった**
  （M-2 は上がる側）。疑似業種は未来情報だったが、OOF の順位を動かすほどには効いていなかった。
  採否の条件にしない方針（決定2）は結果を見る前に決めたもので、この結果でも変えない。
- M-1 の rank-IC は全期で完全に同じ。既定特徴量に業種内Z を持たず、業種は R3 のバケットと業種中立 IC の
  メタにしか効かないため。差の系列がすべて 0 のとき `bootstrap_mean_ci` は p を下限（0.001）として返すが、
  CI が [0, 0] なので有意にはならない（表示上の p だけが紛らわしい）。

## Consequences

- マージ後の最初の夜間 Phase 5 で 517社・財務行 3,954行（通期 2,294・H1 1,660）に業種が入る。M-6 の
  μ̂ は業種内Z を通じて動く（上の OOF の差が目安）。月次の `factor_premia` の重みは業種に依存しないので
  変わらない。
- **33業種外の 70社（約370行）は空のまま残る**。この小さな群は今も「後に廃止した社」の印で、年によっては
  1社になり業種内Z が NULL になる（その行は M-2/M-6 のパネルから落ちる）。埋める先が無いので残す。
- EDINET の分類は廃止時点の JPX の分類と一致する保証が無い（現役社で 4.6% 食い違う・#784）。正本の JPX が
  無い社に限った次善の値として扱う。
- 計測スクリプトは残す（#784・#780 の計測は手順が残らず、再実行できなかった）。業種の付け方を変えるときは
  これで測り直す。
