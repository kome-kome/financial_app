# 静的プリセットの重みは、大小順を保ったまま rank-IC を直接高めて walk-forward で推定する

## Status

accepted（2026-09-19）。Issue [#625](https://github.com/kome-kome/financial_app/issues/625)
（親 [#546](https://github.com/kome-kome/financial_app/issues/546) の前提1）。

- [ADR-0041](0041-preset-weight-gate-has-an-implementation.md)（`preset_ic_gate` を唯一の評価器にする）は
  変えない。本 ADR は推定側を足し、評価は `preset_ic_gate` の関数へ委譲する。
- [ADR-0057](0057-past-gap-ratio-is-reconstructed-as-of-each-month.md)（時点再現の gap_ratio）の
  パネルをそのまま使う。
- `plugins/recommend.py::PRESETS` は変えない。変えるかは #546 が本 ADR の道具の結果を見て決める。

## Context

静的4プリセット（バランス型 / 成長重視 / 割安重視 / 高収益重視）の重みは、#509 で断面標準化を入れる前に
直感で決めた値で、今の前処理とかみ合っていない（成長重視の rank-IC は +0.1264 → +0.0605・ADR-0008）。
#546 はこれを walk-forward で再チューニングする Issue だが、**実行すべきコマンドが1つも無かった**。
`scripts/preset_ic_gate.py` は与えられた重みを測る評価器で、推定はしない。

推定器を作るうえでの設計の中心は2つあった。

1. **何を最大化するか。** 既存の推定手段は Fama-MacBeth（`recommend_factor_premia`・二乗誤差の断面回帰）
   だけだが、プリセットの評価は月ごとの順位相関（rank-IC）で行う。#615 では M-1 に「学習は二乗誤差・
   評価は順位」のずれが見つかり、BIC が相場全体の上げ下げを説明するマクロ列を選んで順位を作る財務列を
   締め出していた。
2. **プリセットの性格をどう残すか。** 無制約で推定すると、4つとも「その期間にいちばん効いた配分」へ
   寄って区別が消える（#625 本文）。静的プリセットの価値は「なぜこの順位になるか」を重みから説明
   できることにある（MODELS.md §6）。

## Decision

### 1. 尺度は rank-IC を直接高める（評価と同じ尺度で学習する）

学習期間の各月 t について Pearson(スコア, 順位化した52週先リターン) を求め、その平均を最大化する。
スコアは標準化済みの列 Z_t の線形結合なので、

```
f(w) = mean_t  w'c_t / sqrt(w'S_t w)
  S_t = cov(Z_t)                         （列の共分散・1/n）
  c_t = cov(Z_t, rank(y_t)) / sd(rank(y_t))
```

の閉形式で書ける。c_t と S_t は月ごとに1回だけ前計算し、最適化は数値だけで回る。解法は SLSQP
（乱数を使わない制約付き最適化）、初期値は静的重み（制約を満たす点）。勾配は解析的に与える。
順位は `_spearman` と同じ平均順位（同点は平均）。

これは Spearman そのものではない（スコア側を順位にしていない）。スコアを順位にすると重みについて
階段状になって勾配が取れないため、リターン側だけを順位にした滑らかな近似を学習に使い、**評価は本物の
Spearman（`preset_ic_gate.ic_series`）で行う**。

### 2. 性格は静的重みの大小順で残す

- 使う指標は静的プリセットのキーだけ（それ以外は 0）
- 重みは非負
- 静的に重い指標は推定後も軽い指標以上（隣り合う水準の組だけで足りる＝推移律）。**同じ重みの指標同士
  には制約を置かない**（例: 成長重視の `z_op_margin` と `z_cf_ratio` はどちらも 0.5 で、入れ替わってよい）
- 重みの合計は静的と同じに固定する。順位は重みの定数倍で変わらないので、見比べるための正規化

新しい閾値を持ち込まない。主軸（最大の指標）が主軸のまま残り、下位の指標はゼロまで下げられる
（＝使う指標を減らす余地はあるが、増やす余地は無い）。バランス型にも同じ規則がそのまま効く。
静的重みがすべて正であることが前提で、負の重みを持つプリセットが足されたら推定器は `ValueError` で止まる。

### 3. 標準化は消費側の関数をそのまま通す

`preset_ic_gate._panel_rows` → `build_view_stats` → `standardize_metric`（ADR-0041 Decision 2 と同じ）。
列の統計（`fit_zscore_stats` の winsorize 済み mean/sd）は他の列の重みに依存しないので、全列を重み 1.0 で
渡して一度に作ってよく、`Z w / Σ|w|` は `preset_ic_gate.score_period` のスコアと一致する。
**最適化しているスコアと評価しているスコアが同じもの**であることをテストが縛る
（`TestScoreMatchesConsumer`）。

### 4. embargo は 12か月に固定し、学習月は暦で切る

目的変数は52週先リターンなので、テスト月との差が12か月以内の月のラベルはテスト月の時点でまだ確定して
いない。`plugins.macro_snapshots.LABEL_HORIZON_MONTHS`（=12）を使い、**CLI の引数にしない**（下げると
先読みになる）。学習月は「テスト月との差が12か月より大きい月」を暦で判定する。月の抜けが無ければ
`walk_forward_cv_monthly` の `all_yms[:i-12]` と同じ集合で、抜けがあっても境界がずれない
（並びの位置で12個戻ると、抜けた分だけ確定済みのラベルを余計に捨てる）。
学習期間の最小月数は 18（`walk_forward_cv_monthly` の既定）。既定は拡大窓で、`--window-months` で
ローリング窓にできる。テスト月は1か月ずつ進める。

先読みが無いことは「テスト月から12か月以内とそれより後の月の X・y を壊しても、その月の推定重みが
1ビットも変わらない」ことで縛る（`TestNoLookahead`）。

### 5. 昇格の根拠は OOF の対比較だけ

テスト月ごとの推定重みで、その月の rank-IC を `preset_ic_gate.ic_series` に1期だけのパネルとして渡して
測る（評価を書き直さない）。同じ月の集合で静的重みの rank-IC も測り、`paired_ic_significance`
（定常ブートストラップ）で対にし、Bonferroni（推定したプリセット数）で判定する。判定文は符号でなく
補正後 α で書く（ADR-0028 規則2）。

`--weights-out` は全月で推定した最終重みを `preset_ic_gate --weights-json` の形で書き出すが、
**これを `preset_ic_gate` で測る比較は in-sample**（学習に使った期間での成績）で、推定した側が有利に
見えるのは当然なので、昇格の根拠にしない。

最適化が収束しなかった月は OOF 系列から外して数える。静的重みで埋めると差が 0 に寄り、黙って
「差なし」側へ倒れる。

### 6. パネルは時点再現の gap あり。DB へは書かない

`build_period_panel(with_gap_ratio=True)`（ADR-0057）。4プリセット中3つが `gap_ratio` を使う。
ADR-0057 の載せる基準を満たさなければ推定せず exit 2。出力は JSON だけで、書き出しは全計算の完走後。
`run_daytime.JOBS["wf:preset-weights"]` に登録する（`parallel_sensitive=False`＝閉形式のモーメント・
SLSQP・seed 固定のブートストラップで、裏で何が動いても同じ入力から同じ答えが出る）。

## 実測（2026-09-19・ローカル正本・夜間バッチ終了後・並走なし）

`python -m scripts.preset_weight_walkforward --json --weights-out`。所要 **1.9分**（時点再現の gap 込みの
パネル構築を含む）。

- パネル: 62期（2020-07..2025-08）・社数 中央値 3,191 / 最小 2,913 / 最大 3,404。gap の基準は MEETS
  （減少率 中央値 2.56%・最大 2.87%）
- embargo 12・学習の最小 18か月・拡大窓 → テスト月は **2023-01..2025-08 の32か月**。4プリセットとも
  未収束 0
- Bonferroni α = 0.05 / 4 = **0.0125**

### OOF の対比較（昇格の根拠になる唯一の比較）

| プリセット | 推定（wf） | 静的 | 差 | 95%CI | p | 判定 | 推定が上回った月 |
|---|---|---|---|---|---|---|---|
| バランス型 | +0.0927 | +0.0843 | +0.0084 | [−0.0043, +0.0193] | 0.198 | ns | 24/32 |
| 成長重視 | **+0.1470** | +0.1113 | **+0.0357** | [+0.0233, +0.0475] | 0.001（下限） | **SIG** | **32/32** |
| 割安重視 | +0.0913 | +0.0771 | +0.0142 | [+0.0006, +0.0287] | 0.047 | ns（補正前なら有意） | 23/32 |
| 高収益重視 | +0.0451 | +0.0335 | +0.0116 | [−0.0048, +0.0309] | 0.168 | ns | 20/32 |

p=0.001 は `n_boot=2000` の下限（ADR-0041 Decision 5）で、それ以上小さいことを意味しない。

### 最終重み（全62か月で推定・合計は静的と同じ）

| プリセット | 静的 | 推定 |
|---|---|---|
| バランス型 | roe 1.0 / op 1.0 / rev 0.8 / cf 0.8 / eq 0.5 / gap 0.5 / mom 0.5 | roe 1.073 / op 1.073 / rev 1.073 / cf 0.940 / **eq 0** / gap 0.940 / **mom 0** |
| 成長重視 | rev 2.0 / roe 1.0 / op 0.5 / cf 0.5 / gap 0.3 | **rev 2.504** / roe 0.449 / op 0.449 / cf 0.449 / gap 0.449 |
| 割安重視 | gap 2.0 / roe 1.0 / op 1.0 / eq 0.5 | gap 2.562 / roe 1.563 / op 0.375 / **eq 0** |
| 高収益重視 | roe 2.0 / op 2.0 / cf 1.0 / eq 0.5 | **roe 5.365** / op 0.135 / **cf 0** / **eq 0** |

fold ごとの推移（32か月）も同じ形で、`z_equity_ratio` と `z_momentum` は全 fold で 0、成長重視の
`z_revenue` は 2.66〜3.24 の範囲に収まった。

### 同じ最終重みを `preset_ic_gate` で測ると（in-sample・**根拠にしない**）

`python -m scripts.preset_ic_gate --with-gap-ratio --preset …（4つ）--weights-json scripts/.cache/preset_weight_walkforward_weights.json`
では、**推定した4つとも**バランス型（静的）に対して補正後 α（0.0071・7検定）で有意に見えた
（例: バランス型(wf) +0.0651 対 +0.0382）。OOF では有意なのは成長重視だけで、バランス型の差は
+0.0084・ns に縮む。学習に使った月で測れば推定した側が良く見えるのは当然で、**決定5で in-sample を
根拠にしないとした理由がそのまま数字に出ている**。静的の値（バランス型 +0.0382 / 成長重視 +0.0768 /
割安重視 +0.0528 / 高収益重視 −0.0092）は ADR-0057 の実測と 0.0003 以内で一致した（データ世代差）。

### 読み

- **成長重視**は全32か月で推定が静的を上回り、補正後も有意。推定は `z_revenue` を主軸として強め、
  下位4指標を同じ重みに均した（`z_roe` 1.0 → 0.449 と、`gap_ratio` 0.3 → 0.449 が同じ水準で止まる＝
  大小順の制約が効いている）
- **高収益重視は `z_roe` 単独へ寄った**（`z_op_margin` 0.135・`z_cf_ratio` 0）。静的で `z_roe` と
  `z_op_margin` が同値（2.0）なので、決定2の「同値同士は自由」により片方へ寄れる。大小順の規則には
  反していないが、「高収益重視」が2指標の配分でなくなる。しかも OOF の差は ns。#546 で反映を考えるときは、
  この形を性格として受け入れるかも判断に含める
- **`z_equity_ratio` と `z_momentum` はどのプリセットでも 0** になった。どちらも各プリセットの最下位の
  水準なので、大小順の内側でゼロまで下げられる

## Consequences

- #546 に実行すべきコマンドができた。#546 の前提は2つとも満たされた（前提2 は ADR-0057）
- `PRESETS` は変わらない。本 ADR の OOF 比較で補正後 α を通ったプリセットだけを #546 で反映する
- 推定は大小順の内側でしか重みを動かさない。大小順そのものが間違っている（例えば主軸が効いていない）
  場合、この推定器はそれを直せず、主軸を下位と同じ重みまで下げたところで止まる。それが見えたら、
  性格そのものを変えるかは別の判断（プリセットの定義の変更）になる
- 代理目的（リターン側だけ順位）と評価（Spearman）は一致しない。学習期間の代理 IC が上がっても
  OOF の Spearman が上がる保証は無く、それを確かめるのが決定5の対比較
- パネルは毎晩伸びる。過去の実測と比べるときは `--until <ym>` で期を揃える（ADR-0041 と同じ）

## Considered Options

- **A. rank-IC を直接高める（採用）**
- **B. Fama-MacBeth（`fama_macbeth_regression`）をプリセットの指標に限定して流用** → 却下。
  学習（二乗誤差）と評価（順位）の尺度がずれる（#615 と同型）。非負と大小順を課すには制約付き回帰へ
  書き換えが要り、流用の利点が薄れる
- **C. 指標単独の rank-IC に比例して配分** → 却下。最も単純で過学習しにくいが、指標間の相関を無視する。
  `z_op_margin` と `z_cf_ratio` は分母（`pl_revenue`）が共通で相関が高く、似た指標が二重に効く
- **性格: 主軸だけ最大を保つ** → 却下。バランス型の主軸は高収益重視と同じ（`z_roe`・`z_op_margin`）で
  両者が似た重みに寄りやすく、防ぐには「1指標は全体の 1/3 まで」のような閾値を新たに決める必要がある
- **性格: 静的重みの 0.5〜1.5 倍の帯** → 却下。性格は最も強く残るが、改善できる幅も小さく、帯の幅に
  根拠が無い
- **性格: 使う指標と符号だけ固定** → 却下。4つが同じ重みへ寄る懸念（#625 本文）がそのまま残る
