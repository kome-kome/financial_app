# 連結の値が無い列は補完せずに外し、回帰に入らなかった社の古い乖離率は消す

## Status

accepted（2026-10-11）。Issue [#905](https://github.com/kome-kome/financial_app/issues/905)
（[#896](https://github.com/kome-kome/financial_app/issues/896) の範囲外として切り出した残り）。

- ADR-0027 の「構造的 NULL は業種単位で外し、0 埋めは `dps` だけ」を**そのまま延長する**（置き換えない）。

## Context

#896 で、連結財務諸表を作る会社の書類からは、財務諸表の列に単体（`NonConsolidatedMember`）の値を
採らなくなった（PR #907）。連結の値が無い列は空欄になり、営業利益が空欄なら `op_margin` も空欄になる
（以前は `COALESCE(営業利益, 0)` で 0%）。新しく読む書類にはすぐ効き、既存の行は #900 の掃除で空欄になる。

2026-06-16〜30 提出の有報 55件で書類単位に数えた見積り（#905）:

| 会計基準 | 書類 | sector_ols の既定列のどれかが空欄になる書類 | 内訳 |
|---|---|---|---|
| US-GAAP | 5 | 5 | 営業利益・負債（全社）、売上総利益（4社） |
| IFRS | 15 | 5 | 売上総利益（ホンダ・ソニー・武田）、営業利益（日立・ソフトバンク G） |
| 日本基準（連結） | 33 | 0 | — |

空欄になった社は、使う列が1つでも空欄の社を丸ごと外す4つの母集団から外れる:
`sector_ols`（`_classify_by_sector` の AND）、M-2 `macro_gbdt` と M-6 `macro_enet`（`build_snapshots`。
既定の財務特徴量は `FIN_BASE_OPTIONS` 全部で `op_margin` 系を含む）、factor premia（`build_period_panel`。
`z_op_margin` を含む7列）。

調べると、外れること自体より悪い経路が1本あった。**`sector_ols` の保存は上書き（upsert）だけで、
削除をしない**。回帰から外れた社には前回までの `regression_results` の行が残り、`financial_metrics`
VIEW が同じキー `(edinet_code, year, period_end)` で結合するので、乖離分析と買い推奨のバランス型に
出続ける。#900 の後は、それが**単体の値（誤り）から計算した乖離率**になり、次の晩以降も上書きされない。
M-2・M-6 の保存は毎回の全件置き換え（`replace_macro_*_scores`）なので、この問題は無い。factor premia は
推定に完全な行だけを使うが、推奨の採点（`recommend.py::weighted_score`）は欠けた指標を外して重みを
配り直すので、社が推奨から消えるわけではない。

## Considered Options

1. **除外を受け入れる**（採用）: 取れなかった値を推測で埋めない。
2. **業種内の中央値などで補完する**: 日立（IFRS の営業利益を載せず、調整後営業利益・EBIT を使う）や
   ソフトバンク G（営業利益の概念が無い）のような**正当な欠損に、存在しない数字を作る**。ADR-0027 でも
   「補完値は観測ではない」として却下した案で、どの列なら補完してよいかの基準も無い。前処理を変えるので
   `PREPROCESS_VERSION` の判断と実測も要る。
3. **`sector_ols` の既定の説明変数から `ps_gross_profit` を外す**: IFRS で欠けやすい列を落とせばソニー等は
   戻るが、日本基準の約3,000社の粗利の情報を捨て、全社の回帰式が変わる。日立のように営業利益を欠く社は
   戻らない。業種内で 30% を超えて欠ける列は ADR-0027 の業種単位の間引きがすでに外している。

## Decision

1. **連結の値が無い列は補完せず、その社をその母集団から外す**（案1）。
2. **`sector_ols` は、今回読んだ行のうち回帰に入らなかった行を `regression_results` から消す**
   （`SectorOLSPlugin._prune_unwritten` → `database.delete_regression_results`）。
   - 消す対象は「今回読んだ行（各社の最新の通期行、`year` 指定ならその年度）のキー − 回帰に入った行のキー」。
     列の空欄・株価の欠落・業種が `min_samples` を割った、のどれで外れても同じに扱う。
   - **過去の年度の行と、`tradable_filters` で読まなかった廃止・停止の社の行には触れない**
     （後者は #780 で残すと決めた。表示は `tradable_filters` が隠す）。
   - **1業種も当てはめられなかった回は消さない**（設定の誤りやデータ不足で表を空にしない）。
   - 画面からの手動実行でも消す。表はもともと「最後の実行の結果」へ上書きされるので、外れた社だけ
     前回の値が残る方が混ざって誤解を生む。
   - 判定は回帰に入った行から行い、`_persist_and_rank` の戻り値には頼らない。**書き込みを止めて測る
     スクリプト（`scripts/measure_sector_coverage.py`）は `_prune_unwritten` も差し替える**——
     upsert だけ止めると、設定ごとに外れた社の行が正本から消える。
3. **外したことを黙らない**。`sector_ols` の結果に `n_excluded_missing`（採用列の空欄で外した社数）・
   `excluded_by_feature`（列ごとの社数。1社が複数の列で数えられうる）・`n_removed_stale`（消した行数）を
   足し、画面の警告と夜間の診断値（`nightly_model_diagnostics`・ADR-0061）に出す。
4. **`PREPROCESS_VERSION` は上げない**。winsorize と標準化の手順は変えていない。

## Consequences

- #900 の適用後、ソニー・日立・US-GAAP の社などは乖離分析から消え、M-2・M-6 の予測と factor premia の
  推定からも外れる。以前は誤った単体の値で入っていたので、正しさの面では改善である。
- 母集団が縮むので、モデル同士の比較は共通域で測り直す（ADR-0045・ADR-0050。縮む側は必ず有利に見える）。
  #900 の手順5（適用前後の採用社数の比較）は、夜間の診断値の3つの数を読めば済む。
- `regression_results` の行は「今回の回帰に入った社」と一致するようになる。最初の夜間で消える行は、
  #900 の前でもすでに母集団から外れていて同じキーの古い行を持っていた社のぶんで、件数は
  `n_removed_stale` に出る。
- 残る課題は別 Issue で扱う: M-2 だけ財務の空欄をそのまま学習に通す案（XGBoost は欠損を扱える。
  母集団を動かすので共通域で測ってから）、`financial_metrics` VIEW が借入金・負債合計の空欄を 0 として
  計算するため #900 の後に US-GAAP の社の D/E が 0・ネットキャッシュが歪む件。
