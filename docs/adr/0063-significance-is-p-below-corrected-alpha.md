# 比較の有意判定は p 値と補正後 α で行い、CI は同じ α の区間を添える

## Status

accepted（2026-09-26）。Issue [#741](https://github.com/kome-kome/financial_app/issues/741)。
`model_stats` の有意判定（#369 で「95% CI が 0 を跨がなければ有意」として入った・ADR は無い）を置き換える。
[ADR-0041](0041-preset-weight-gate-has-an-implementation.md) §5「Bonferroni は検定数から機械が出す」を、
比較画面と bakeoff スクリプトへ広げる。[ADR-0021](0021-sibling-model-candidate-menu.md)・
[ADR-0028](0028-freshness-limits-from-measured-release-lag.md)・[ADR-0044](0044-retire-underperforming-models-by-hiding.md) の
判定の書き方（p と補正後 α）は変えず、コードの側をそれに揃える。

## Context

比較画面（`/api/backtest/model-comparison`）は6モデルを2つずつ組にして（15組）、月ごとの rank-IC の差を
定常ブートストラップで検定し、▲/▼/n.s. を出している。15組を同時に検定するなら基準を 0.05 ÷ 15 ≒ 0.0033 に
下げなければならない（補正しないと、差が無くてもどれか1組が偶然有意に見える確率は 1 − 0.95¹⁵ ≒ 54%）。

2026-09-26 の時点で、次の2つが重なっていた。

1. **alpha が判定に届いていなかった。** `significance_matrix(alpha=...)` の `alpha` は戻り値へ書き戻されるだけで、
   `paired_ic_significance` は常に `bootstrap_mean_ci` の既定 0.05 で CI を作り、`significant` を
   「95% CI が 0 を跨がない」で決めていた。比較画面は alpha を渡してすらおらず、15組を補正なしで判定していた。
   `preset_ic_gate` は Bonferroni の alpha を渡していたが、正しい結論になっていたのは自前で `p_value` を
   読み直していたからである。引数を渡した側からは補正したように見えるので、**失敗として現れない**。
2. **判定のやり方が2つに割れていた。**

   | 規則 | 使っていたところ |
   |---|---|
   | 「CI が 0 を跨がない」（`significant` を読む） | 比較画面・`model_comparison_run`・`candidate_bakeoff`（8組）・`ensemble_base_bakeoff`（3組） |
   | 「p < 補正後 α」 | `preset_ic_gate`・`macro_feature_bakeoff`・`macro_dlm_feature_bakeoff`・`momentum_gate`・`preset_weight_walkforward`、および ADR-0021（p=0.002 < α/8）・ADR-0028 規則2・ADR-0044（退役） |

   2つは境界で食い違う。n_boot=2000・α=0.0033 のとき、ブートストラップ平均が 0 以下になった標本が
   3個なら、CI の規則では有意（下側 0.17% 点は4番目と5番目の間で正）、p の規則では p = 2×4/2001 = 0.0040 で
   有意でない。画面が ▲ を出すのに、正式な手続きでは有意でない、ということが起こりえた。

## Decision

### 1. 有意は「p < α」かつ「同じ α の CI が 0 を跨がない」

`model_stats._is_significant` を唯一の規則にする。p は返り値と同じ4桁丸めの値で比べる（画面とスクリプトが
並べる数字と同じもので判定する）。

p の規則は CI の規則より厳しい側にある。0 以下の標本数を k、下側の分位点の位置を (N−1)α/2 とすると、
p < α ⇔ k < α(N+1)/2 − 1 < (N−1)α/2 なので、p が α を下回れば CI の下端は必ず正になる。したがって
この規則は実用上「p < α」と同じで、CI 側の条件は、p の丸めの端で「▲ なのに表示の CI が 0 を含む」が
起きないための安全装置である（MODELS.md §15.4 の昇格ゲートも両条件を併記している）。

CI は判定と同じ α の (1−α) 区間を返す。p は α に依存しない。

### 2. 補正は家族単位の関数が組数から出す

`paired_family_significance(pairs, alpha=0.05, correction="bonferroni")` が、共通期が2以上ある組
（＝実際に検定する組）を数えて m とし、1検定あたりの α = alpha / m で各組を判定する。検定できない組は
数えない（ADR-0041 §5 と同じく、検定数は実際に走らせた数から機械が出す）。`significance_matrix` はこの上に
載り、比較画面・`candidate_bakeoff`・`ensemble_base_bakeoff` もこれを使う。組数を書き写すと1つだけ古くなる。

複数の組を扱う関数の `correction` の既定は `"bonferroni"` にする（書き忘れたときに補正なしへ倒れない向き）。
`"none"` は呼び出し元が補正済みの α を持つ場合（`preset_ic_gate` の all-pairs）のためにある。
単発の `paired_ic_significance(alpha=0.05)` は1検定の関数のままで、補正の概念を持たない。

### 3. 家族は「画面に並べた組すべて」

比較画面は退役済みの M-4/M-5 を含む6モデルの15組を数える。どのセルからも結論を読めるので、並べた組は
すべて検定として数える。CLI の `--models a,b`（退役の実測・#570）は1組＝ α 0.05 のまま変わらない。

### 4. 表示は生の p と補正後 α、CI は同じ α の水準で

画面と CLI は p を補正前の値のまま出し、補正後 α と「0.05 ÷ m 組」を併記する（スクリプト群の
`p=… SIG(alpha=…)` と同じ流儀）。「95%CI」を焼き付けず、`ci_level_label(alpha)`（15組なら 99.67%）で出す。

### 5. p の下限を下回る α は印で知らせる

`bootstrap_mean_ci` の p は 2/(n_boot+1)（n_boot=2000 で 0.0010）を下回らないので、1検定あたりの α が
それ以下になると、差がどれだけ大きくても有意にならない。n_boot=2000 では 55組（11モデル）以上で起きる。
戻り値に `alpha_below_p_floor` を立て、画面と CLI が注意書きを出す。

### 6. `preset_ic_gate` の出力は変えない

all-pairs モードは `correction="none"`・既定 α で matrix を呼び、行の CI は他のモードと同じ 95% のまま出す
（判定は従来どおり自前の p < 補正後 α）。ADR-0041 の記録値を再現する手続きに触れないためである。
変更前後で `--compare-standardization` と `--all-pairs` の標準出力が1文字も変わらないことを確かめた
（2026-09-26・61期・`--until 2025-07`）。

## Consequences

- **画面の ▲ と、昇格・退役の正式な手続きが同じ答えを出す。** 15組の画面は α=0.0033 で判定するので ▲ は減る。
  過去の決着（M-6 > M-2 の p=0.002、M-2 > M-5 の p=0.001）は、記録値のままなら補正後も基準を下回る。
- **既定 α=0.05 の単発検定は、境界の1標本ぶんでしか答えが変わらない。** mean・CI・p は変更前と完全一致
  することを合成系列で確かめた。
- **`candidate_bakeoff`・`ensemble_base_bakeoff` を次に回すと表示が変わる。** 「有意」の列が補正後の判定になり、
  CI も補正後の水準で出る。ADR-0021・ADR-0015 の表は当時の 95% CI の記録であり、書き換えない。
- **p の下限による上限がある。** モデルが 11 本以上に増えたら n_boot を上げるか、家族を分ける判断が要る
  （印が出るので黙って「全部 n.s.」にはならない）。
- ゲート系5本が各自で α を計算している箇所は、出力が正しいので本件では家族関数へ寄せていない。

## Considered Options

### 案A: CI の規則のまま alpha だけ効かせる（#741 の当初案）

`paired_ic_significance` へ alpha を通し、CI の幅だけを α に従わせる。既定 α の呼び出し元は1ビットも変わらず、
変更は最小になる。しかし判定のやり方が2つ残り、上の境界（0 以下が3個）で画面は ▲、ツールチップの
p=0.0040 は α=0.0033 を上回る、という見た目の矛盾が残る。正式な手続きと画面の答えがずれうるので採らない。

### 案B: Holm 補正

Bonferroni より検出力が高く、同じく家族全体の誤り率を抑える。しかし ADR-0021/0028/0041 と全ゲート系
スクリプトが Bonferroni で、画面だけが別の補正法になると、同じ実測に2つの答えが出る。採らない。

### 案C: 現役の既定モデル（M-6）との比較だけを家族にする

家族が5組になり α=0.01 で済む。しかし画面は15組すべてを並べ、どのセルからも結論を読める。
並べたものを数えないのは補正の意味を失わせるので採らない。

### 案D: n_boot を増やして p の下限を下げる

15組では下限（0.0010）が α（0.0033）を下回っているので、今は要らない。上げると過去の全記録の p が
動く（ADR-0041 の p=0.001 は下限）。下限を超えたときは印が出る（決定5）。
