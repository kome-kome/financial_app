# 指数イベントは企業イベント台帳と分け、公式リストの登録表から公表日 as-of で時点再現する

## Status

accepted（2026-10-21）。Issue [#1003](https://github.com/kome-kome/financial_app/issues/1003)（台帳）・
親 [#1001](https://github.com/kome-kome/financial_app/issues/1001)（TOPIX 定期入替の指数効果）・
資料 [#1002](https://github.com/kome-kome/financial_app/issues/1002)。

- この ADR は #1001 の記録先を兼ねる（`docs/prereg/index-event-2026.md` の冒頭）。計測の実走と手当ての採否は、
  凍結版の sha256 と並べて末尾の「#1001 の記録」へ追記する。

## Context

TOPIX の初回定期入替（2026-10-07 公表・2026-10-30 反映）で、683 社が移行措置（浮動株比率に移行係数を掛けて
2028-07 まで 8 回でウエイトを下げ、最後に除外）、35 社が新規採用（係数 0.75 で組み入れ）になった。
2022-10 にも同型の段階的ウエイト低減（493 社）があり、指数連動資金の売りが業績と無関係に価格を動かす。
本番の予測がこれで歪むかを測る（#1001）には、「どの社が、いつ、どの指数イベントの対象で、その日の係数は
いくつで、それはいつから分かっていたか」が要る。

その履歴は DB に無かった。`companies.market` は全社 NULL（#1015）、data_j の規模区分と J-Quants の `ScaleCat`
は移行措置を区別しない。**JPX の公式一覧（PDF）だけが唯一の源**になる。

一方、株数や株価の基準を変える企業イベントは `corporate_actions.py` の台帳 1 つに置く（ADR-0062）。
指数イベントも「社×日付のイベント」なので、同じ台帳へ足す形も考えられた。

## Decision

### 1. 別の module（`index_events.py`）にし、F・TTM・`tradable_filters` へ流さない

企業イベント台帳は分割補正係数 F（`financial_metrics` VIEW の per / pbr / market_cap・ADR-0055）と
TTM（ADR-0051）へ毎晩流れる。指数イベントは 1 株の基準を変えないので、混ぜても F・TTM には何も足さず、
読み手の数だけ波及の経路が増える。`corporate_actions` / `ttm_composite` / `database`（`tradable_filters` を含む）
が `index_events` を import しないことをテストで固定する。並び（登録表 → 純関数 → 台帳 → I/O）と、
I/O より上が database / scripts をトップで import しないことは ADR-0062 に揃える。

### 2. 一覧はリポジトリに入れず、登録表と正規化 CSV の sha256 だけを入れる

JPX の資料には無断転載不可の明記があり、リポジトリは PUBLIC。一覧は `.index_lists/`（`.gitignore`）に置き、
`scripts/import_index_list.py` が `sec_code,kind` の正規化 CSV にする。コミットするのは登録表
（公表日・引け後か・反映日・件数・元資料と正規化 CSV の sha256・出典・確度・根拠）だけ。
元資料の sha256 は「どの資料か」、正規化 CSV の sha256 は「台帳が読む中身が取り込み時と同じか」を固定する。
検体も銘柄の並びを写さず、見出しと書式だけを写す。

### 3. 照合は登録表の値で閉じ、合わなければ止まる

- 件数は事前登録の照合値（493 / 43 / 439 / 35〔スタンダード 23・グロース 12・プライム 0〕/ 683 / 1,669）。
- 前後の一覧の差は、期間中の上場廃止等（`DELISTED_DURING`）とコードの承継（`CODE_SUCCESSIONS`）で
  過不足なく説明できなければ止まる（暗黙の残差にしない）。2022→2023 は消えた 13 = 上場廃止等 11 ＋ 承継 2。
  承継は社名と上場状態からの推定で `confirmed=False`。d2（2023-10〜2025-01 の上場廃止等）は手元の
  データでは社ごとに決められない（`delisted_date` は同期が気づいた日）ので**未登録（`None`）**として持ち、
  空（登録済みで 0 社）と区別する。2025-01 の除外数は d2 が入るまで出さない。
- 証券コード → edinet_code の突合率は**一覧ごとの重複なしのコード集合**で 98% 以上。節ごとに測ると、
  上場直後の 1 社が企業表に無いだけで新規追加 35 社が 97.1% になる。未突合は理由別に数えて出す。
- 一覧のファイルが無いだけなら `ok=False` と理由を返す（黙って空にしない）。壊れていれば例外。

### 4. 時点再現: 公表日 as-of・無い≠無し・未登録の見直しの先は分からない

- `status_at(ledger, ec, on, known_at)` は `known_at` で見えていた一覧だけを使う。**引け後の公表は翌日から
  見える**（公表日の終値で計算する処理に先読みを入れない）。
- どの一覧にも無い社は `unknown`。「継続」と決めつけない（2022 には構成銘柄の全一覧が無い）。
- 結果がまだ台帳に無い見直し（2027-10 の再評価・2028-10 の定期入替）より後の日付は、係数を `None`・
  状態を `pending` にする。次に来る見直しは `next_review_expected()` が返す（#1014 の watchdog の元）。

### 5. 係数は式で、日付は手で入れて根拠を付ける

係数は `1 - m * step`（`Fraction`）で持ち、丸めた小数を書き写さない。指数修正日は事前登録文書 §3 の表と
同じ値を手で入れ、日付ごとに「一次資料」か「規則からの推定」を持つ（テストで表と 1 行ずつ照合する）。
祝日表（`scripts.run_daytime.HOLIDAYS`）は使わない——2026・2027 しか持たず、人の在宅の都合も含み、
東証の休業日とも違う（ADR-0062 決定4 の「本番は `scripts/` を import しない」にも当たる）。

### 6. PDF の文字は Git 同梱の `pdftotext` で取り出す

一覧は PDF しか無い。Git for Windows 同梱の `pdftotext`（Xpdf 4.00）の `-enc UTF-8 -table` で、3 本とも
件数と通し番号が公表値と完全に一致した（2026-10-21）。取り込みは手元でしか走らない CLI なので、
Python の PDF ライブラリ（CVE 評価と承認が要る）を入れずに済ませる。取り出しの崩れは、節ごとの通し番号の
連続・件数・市場区分の内訳・正規化 CSV の sha256 の 4 段で止まる。

## Consequences

- 後続（#1006 露出・#1008〜#1011 計測・#1013 画面・#1014 年次運用）は `status_at` / `group_labels` /
  `panel_index_status` / `members` を呼ぶだけで、群分けとパネルへの付与ができる。
- Render には一覧が無いので、本番の画面から使うときは常に `ok=False`（#1013 はバナーで扱う）。
- 新しい公表（2027-10 の再評価・2028-10 以降の定期入替）は、資料を `.index_lists/raw/` に置き、登録表の
  `EXPECTED_REVIEWS` から `REVIEWS` へ移して取り込む。2026-11 以降の非定期追加の受け口はまだ無い
  （実例が出てから作る・#1023）。
- 2022 前例の R0（事前登録 §2）は d2 が登録されるまで閉じない（#1022）。2026-10-28 に JPX の上場廃止銘柄
  一覧から 15 社を登録した（2025-01 の除外数 424）。

## Considered Options

### 案A: 企業イベント台帳（`corporate_actions.py`）へ足す

置き場は 1 つで済むが、毎晩 F と TTM へ渡す台帳に、どちらにも効かないイベントが乗る。誤登録が F の
計算経路のそばに置かれ、読み手ごとに「読むべきか」を判断する ADR-0062 以前の形に戻る。**不採用。**

### 案B: 一覧を DB の表へ取り込む

SQL で引ける利点はあるが、表が増え（`init_db`・ミラー・バックアップ）、本番（Supabase の断面）へ一覧の
中身が載る。PUBLIC なリポジトリから辿れる場所へ転載不可の一覧を置かない方針と合わない。**不採用。**

### 案C: Python の PDF ライブラリ（pypdf・pdfplumber 等）で取り出す

依存の追加に CVE 評価と承認が要り、表の行の並びの扱いを別に書く必要がある。`pdftotext -table` で完全に
一致したので採らない。Git 同梱の版が使えない環境では `--pdftotext` で場所を渡す。**不採用。**

## 追記（2026-10-29・#1065）: TOPIX 以外の指数の一覧は台帳に入れない

グロース 250 の定期選定（2026-10-30・追加 31・除外 52）を、2026 群の前向き監視の交絡として数える（事前登録 §9）。
**`REVIEWS` には入れず、別の登録表 `CONFOUNDER_LISTS` に同じ `Review` 型で持つ**（ユーザー判断）。`status_at` は
見えている最新の公表を取るので、`REVIEWS` に入れると TOPIX の状態・C1 対照・画面のタグ・露出がグロース 250 に
上書きされる。読むのは `confounder_members` だけで、元資料と正規化 CSV の sha256・件数の照合は決定 2・3 と同じ。
追加と除外は種別（`g250_add` / `g250_remove`）で分ける（向きが逆の圧力のため・ユーザー判断）。資料は左右 2 列の
表なので、`import_index_list` に 2 列の読み取り（sections の `left` / `right`）を足した。
