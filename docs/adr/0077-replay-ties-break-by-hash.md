# OOF 運用再現の同点は、コード順でなく (期, 社) のハッシュの順で割る

## Status

**accepted（2026-11-18）**。#1259（ユーザー判断 2026-11-18）。親 #1227 の事前登録
[`docs/prereg/portfolio-construction.md`](../prereg/portfolio-construction.md) §6 が「同点の規則を新しい ADR で決めてから
手続きを直す」と定めた、その ADR。事前登録の凍結し直しと測り直しは #1227 で行う。

## Context

OOF 運用再現（`scripts/oof_portfolio_replay.py` の `replay`・`replay_combined`）は、各期に買いのスコアの高い順に買い、
売りのキーの低い順に売る。同点は EDINET コードの小さい順で割っていた。2026-11-17 の #1227 の計測で、予測が全社同じ値の
期に、コードの最も小さい 10 社（E00004…）をそのまま買い、それが 2〜3 期保有に残っていたことが分かった。

2026-11-18 の `measure:oof-replay-ties`（3 経路・HEAD は `d43d29f` を含む・exit 0・42.9 分）で数えた結果:

| モデル | 全社同じ値の期 | 上位 10 社の境目をまたぐ同点 |
|---|---|---|
| M-1 | なし | なし |
| M-2（既定） | なし | +2 か月の 2025-10（5 社） |
| M-2*（本番の設定） | +0 か月の 2021-02 | +0: 2021-05（409 社）／+1: 2021-03・2021-12／+2: 2021-07・2022-01 |
| M-6 | +1 か月の 2022-03／+2 か月の 2021-04・2022-07・2023-01 | なし |

M-6 は経路の途中の期でも全社同じ値になる。その期は売りのキー（既定は M-6 の μ̂）も全社同じなので、売る社もコード順だった。
「最初の期を外す」では直らない。

## Considered Options

1. **(期, 社) のハッシュの順で割る（採用）**: 毎回同じ結果で、入力の順にも依らず、コード順の偏りが消える。全社同じ値の期は
   事実上の無作為な 10 社になり、期待値は全社平均。境目の同点（M-2* の 409 社のかたまり等）にも同じ規則が効く
2. 全社同じ値の期は入れ替えない（最初の期は現金）: 「モデルが何も言わないなら動かない」に近いが、最初の期が現金になるぶん
   成績が下がり、境目の同点には別の規則が要る
3. 全社同じ値の期だけ別のモデル（例: M-2 既定）の並びで買う: 期の中で 2 つのモデルが混ざり、どのモデルの成績か曖昧になる
4. 全社同じ値の期を共通域から外す: 期の集合がモデルごとに変わり、同じ母集団で比べられなくなる（ADR-0045）

## Decision

- `tie_order(ym, ec)` = `sha256(f"{ym}|{ec}")` を、`replay`・`replay_combined` の**買いと売り**の並びの第 2 キーにする
  （第 1 キーのスコアは変えない）。`hash()` は起動ごとに変わるので使わない
- 社だけでなく期も混ぜる。社だけだと毎期同じ社が先に来て、コード順と同じ種類の固定の偏りになる
- 予測が全社同じ値になる原因（M-6 の内側の交差検証が係数を全部 0 にする・M-2* の木が分割しない、と見られる・未確認）は
  予測モデル側の話で、この ADR では扱わない

## Consequences

- 2026-11-18 より前に記録した OOF 運用再現の数字（ADR-0069 の 2026-11-11・2026-11-16、事前登録
  `portfolio-construction.md` の結果）は旧規則で測ったもの。書き換えず注記を付けた
- 同点が無い期の結果は変わらない（スコアの順はそのまま）
- 上位K社の指標 `plugins/macro_snapshots.py::_top_k_shares`（同点に枠を均等に分ける）・`oof_backtest`・探索は対象外で変わらない
- #1155 の `measure:selection-optimism` は運用再現の部品を参考の列に使うので、この規則で回る
