# 日中枠は暦を持つ（日付で決まる仕事を自分で積み、月次と重なる日は重い計算を出さない）

## Status

accepted（2026-09-16）。Issue [#681](https://github.com/kome-kome/financial_app/issues/681)
（親 [#424](https://github.com/kome-kome/financial_app/issues/424) の子1「供給の回復」の定常化）。
[ADR-0051](0051-latest-results-enter-analysis-as-a-ttm-composite.md) の決定5（供給の回復は
方式の選択と独立に先行する）を実装側で閉じる。[ADR-0042](0042-batch-footprints-need-a-reader.md)
の「閾値は約束から導出する」を、キュー駆動の仕事へ広げる。

## Context

平日日中バッチ（`scripts/run_daytime.py`・#618）は「積み忘れても何も起きず、忘れたことに
気づけない」を避けるためにキューを採った。だが**積むのが人である限り、同じ穴はキューの手前に
残る**。

- H1（半期）の収集は、#647 の修正後の 2026-09-16 に初めて保存まで到達した（saved=3,967・
  `max(period_end)` 2026-07-31）。これは手で積んだ1回ぶんにすぎない。次の波は
  **3月期の H1（9/30 期末・提出期限 11/14）**で、ADR-0051 の実測では「H1 のほうが新しい社」が
  30% から 88% へ跳ねる。11月後半に積み忘れると、TTM 合成（#424 子2）を実装しても鮮度は上がらない
- 会社予想（`statement_disclosure`）も同じで、読む消費者はまだ無いが、J-Quants 無料プランは
  **2年より古い日を返さない**ので、止めた期間はあとから埋められない
- watchdog（`batch_freshness`）はどちらの前進も見ていなかった。しかも ADR-0042 は閾値を
  「cadence ＋ 窓」という**約束**から導くが、この2つには「いつ走るか」の約束がそもそも無かった

調査の途中で、別の穴も見つかった。月次系の3本（月次本体 1日・マクロ・ベータ 2日・M-1 探索
3日）はいずれも **01:00 起動・16時間の窓**で、8:00 からの日中枠と時間が重なる。実測でも
2026-09-01 の月次は 12:19 JST まで、M-1 探索は約12.5時間走った。日中枠を作った動機は
「重い計算の裏で作業をすると結論が変わる」（macro_beta の発散 0 → 344・#618）ことで、
**月次の重い計算と日中枠の重い計算の並走はまさにその条件**になる。日中枠の初回実走は
2026-09-08 なので、まだ起きていない。最初に起きるのは 2026-10-01（木）だった。

## Decision

### 1. 日付で決まる仕事は暦（`SCHEDULE`）が積む

`run_daytime.SCHEDULE` に `Scheduled(job, day, produced, source, why)` を並べ、実走の冒頭で
**毎月 `day` 日以降の最初の実走で、キューの先頭へ1回だけ積む**。

| 仕事 | day | 理由 |
|---|---|---|
| `disclosures` | 1 | 84日遅れで届き、提出日の集中が無い。1日は月次と重なる日（下記2）なので、その日の枠を収集で使えば日中枠がまるごと空かない |
| `interim` | 16 | 半期報告書の期限は期末＋45日で、月末期末なら12通りのうち11通りが14〜15日に来る（1月末期末だけ 3/17 で翌月に取る） |

- **先頭へ積む。** 末尾だとキューの長さぶん待ち、待ちに上限が無くなって閾値を約束から導けない。
  先頭なら待ちは「土日（72時間）＋同日に期限を迎えたもう1件（24時間）」で頭打ちになる
- **今月ぶんが既に入っていれば積まない。** 判定は成果物の `created_at`（`h1_created_at` /
  `disclosure_created_at`）で行う。`updated_at` は株価の補完など既存行の更新でも進むので使わない
  （#632 で `companies.industry` を証拠にしなかったのと同じ理由）。手で回した月に二重に回さず、
  デプロイ直後（9/16 に手で回した後）も9月ぶんを積み直さない
- **月に1回だけ判定する。** 判定した月を `app_settings.daytime_schedule`（`{job: "YYYY-MM"}`）に
  残す。収集が成果ゼロで終わっても翌日また積むことはない（毎日同じ計算を繰り返す形にしない＝
  `pop_queue` の設計判断と同じ）
- **測れないときは積む側へ倒す。** 収集は冪等で、余計に1回走るだけで済む。積まない側へ倒すと
  次に気づくのは1か月以上先の watchdog になる
- **判断は純関数（`plan_schedule` / `select_job`）に置き**、実走・ドライラン・`--peek`・`--queue`
  が共有する。見せた1件と実際に走る1件をずらさない。`--peek` / `--queue` / ドライランは書かない

### 2. 月次系のバッチと時間が重なる日は、並走に敏感な仕事を取り出さない

- 重なる日は `run_monthly*.TRIGGER_DAY` / `TRIGGER_TIME` / `WINDOW_MIN` と日中枠の
  `TRIGGER_TIME` / `WINDOW_MIN` から**導く**（`monthly_overlap_days()`）。**実測の所要では
  判定しない**——マクロ・ベータは実測 380分で 8:00 前に終わる月が多いが、窓は16時間ある。
  起動日時の定数は `install_*_task.ps1` の既定とテストが照合する
- その日は `parallel_sensitive=False` の仕事（収集）を**先頭から探して**取り出し、残りの順番は
  崩さない。無ければ何も取り出さず exit 0（足跡は残す＝「起動しなかった」と区別できる）
- 未知の名前は判断材料が無いので敏感側に倒す（`--peek` と同じ方針）
- **`-Now -Force` でも見送る。** `-Force` は「人が PC を触らない」約束であって、月次バッチが
  同じ時間に走ることは変えられない

### 3. 暦の仕事は成果物の前進で監視する

`batch_freshness.PRODUCERS` に「半期財務（H1）」「会社予想（決算短信サマリー）」を足す。
読み手は暦の判定と**同じ関数**（`Scheduled.produced`）で、閾値は
`SCHEDULE_CADENCE_H`（31日＋`CADENCE_H`＋24時間）＋日中枠の窓＝約35.3日。
積み忘れ・暦の故障・収集の失敗のどれでも「新しい行が入らない」として現れる。
暦に仕事を足したら PRODUCERS にも1行足す（テストが照合する）。

## Considered Options

- **月次本体（毎月1日）のステップにする**: 仕組みは増えないが、窓の空きは67分しかなく、
  提出の多い11月（約2,600件・推定45分前後）は余裕が薄い。提出から最大2週間遅れる
  （3月期の 11/14 提出分が 12/1 に入る）
- **暦の仕事をキュー末尾へ積む**: 重い計算の順番は崩れないが、上記のとおり閾値が導けない
- **会社予想を夜間バッチの毎晩のステップにする**: 鮮度は最も高いが、J-Quants の不調が夜間
  バッチの失敗として起票されるようになり、祝日には数日新しい行が来ないので閾値も広げる必要が
  ある。読む消費者がまだ無いので、月1回で足りる
- **月次との重なりを実行時に検出する**（タスクの `State` を見る）: セッション0から
  タスクスケジューラの状態を読む経路が増え、壊れても失敗として現れない。約束（起動日時＋窓）
  から導くほうが、ADR-0042 と同じ理屈で観測時刻に依存しない

## Consequences

- H1 は毎月16日以降、会社予想は毎月1日以降に自動で入る。**手では積まない**
- 重い計算は毎月最大5営業日（月次と重なる3日＋暦の2日）後ろへずれる。日中枠の実測所要
  （最大 380分）は変わらないので、キューの消化速度が月に約1/4落ちる計算になる
- 2026-10-01（木）の日中枠は、`disclosures` を回し（暦）、10/2（金）は重い計算を見送る。
  10/3 は土曜で日中枠が無い
- 月次系のバッチを足したら `run_daytime.MONTHLY_BATCHES` にも足す（`batch_freshness.WATCHED`
  の月次行とテストが照合する）。起動日や窓を変えたら重なる日は自動で追随する
- 日中枠の起動日時・窓を動かしたときも同じく自動で追随する。ただし夜間バッチ（17:20）との
  関係は従来どおり `test_window_leaves_room_before_the_nightly_batch` が見る
