# D/E の分子は有利子負債にし、構成要素を列で持って VIEW で合計する（銀行・保険は D/E を作らない）

## Status

accepted（2026-10-11）。Issue [#920](https://github.com/kome-kome/financial_app/issues/920)（親）・
[#925](https://github.com/kome-kome/financial_app/issues/925)（1段目＝本 ADR の実装）。

- ADR-0066 の追記（#915）「負債合計が載っていれば借入金の空欄は 0」を**そのまま残し**、銀行業・保険業だけを外す。
- 分子の切り替え（決定3の3段目）は #926、過去の行の取り直し（2段目）は #918 で行う。

## Context

D/E の分子は「短期借入金 + 長期借入金」で、登録タグは日本基準の `ShortTermLoansPayable` / `LongTermLoansPayable`
の2つだけだった。次が分子に入らず、D/E が過小に出ていた（エラーは出ない）。

- 1年内返済予定の長期借入金・コマーシャルペーパー（CP）・1年内償還予定の社債（日本基準）。1つの列には
  1つのタグの値しか入らない（`_apply_row` は優先度の高いタグを1つ選ぶだけで合算しない）ので、既存の列へ
  タグを足しても合計にはならない
- IFRS の連結の借入金。日本基準のタグは IFRS の書類では単体の文脈（`NonConsolidatedMember`）にしか無く、
  IFRS の社の借入金の列には単体の値が入っていた（#896 以降に読む書類では採らず空欄になる）
- 銀行の借用金。銀行は借入を「借用金」で載せるので借入金の列が空欄になり、#915 の規則（負債合計があれば
  借入金の空欄は 0）で **D/E = 0（無借金）に見えていた**。保険も借入金の区分を持たない

2026-10-11 に EDINET の有報 22 書類（2026年3月期）の生の行を読んで確かめた:

| 会計基準 | 連結の BS の載せ方 | 書類 |
|---|---|---|
| 日本基準 | `CurrentPortionOfLongTermLoansPayable`（1年内返済予定の長期借入金） | 住友不動産 S100YI5D・東京ガス S100YH8W |
| 日本基準 | `CommercialPapersLiabilities`（CP） | 三井不動産 S100YHUO・住友不動産・日本郵船 S100YBT6 |
| 日本基準 | `CurrentPortionOfBonds`（1年内償還予定の社債） | JR東日本 S100YC7N・大成建設 S100YBGF・住友不動産・日本郵船・東京ガス |
| IFRS | `jpigp_cor:BondsAndBorrowingsCLIFRS` / `…NCLIFRS`（社債及び借入金） | 三菱商事 S100YB25・武田・伊藤忠・アステラス・KDDI |
| IFRS | `jpigp_cor:InterestBearingLiabilitiesCLIFRS` / `…NCLIFRS`（有利子負債） | トヨタ S100Y8NY・ソフトバンクG |
| IFRS | `jpigp_cor:BorrowingsCLIFRS` / `BorrowingsNCLIFRS`（借入金） | 日立 S100YGBO・ソニー（流動）、リクルート S100YDHL（非流動） |
| IFRS | `jpigp_cor:LongTermDebtNCLIFRS`（長期債務） | 日立 |

- 日本基準のタグは同じ名前で単体の文脈にも並ぶ（#896 の規則で採らない）。JR東日本は 1年内返済予定の長期借入金を
  単体にしか載せていない
- ソフトバンクG は「有利子負債」と別の行に「リース負債」を載せる＝有利子負債のタグはリースを含まない
- **社債だけを別に載せる IFRS の標準タグは無かった**（IFRS の社債は上の合算の行に含まれる）
- **合算の行と内訳の行が同じ文脈に並ぶ書類（#904 の形）は無かった**
- 独自拡張のタグで載せる社: 日立・ソニーの「1年内償還の長期債務」、ソニーの長期債務、ホンダの「資金調達に係る債務」、
  日本製鉄の「社債・借入金及びリース負債」（リースを含む）、NTT の短期・長期債務、不動産・建設各社のノンリコースローン

## Decision

`/grill-me`（2026-10-11・#920 のコメント）で決めた 1〜7 と、#925 の実物の確認で決めた 8〜10。

1. **分子は有利子負債**＝短期借入金 + 1年内返済予定の長期借入金 + 長期借入金 + CP + 社債 + 1年内償還予定の社債。
   **リース債務は除く**（新リース基準の適用＝2027年4月以降に始まる年度までは日本基準と IFRS で扱いが違う）。
   「負債合計 ÷ 純資産」は `100 ÷ 自己資本比率 − 1` で `z_equity_ratio` と並び順が一致し、新しい情報にならない
2. **構成要素ごとに列を持ち、合計は VIEW の `interest_bearing_debt` 1か所で作る**。足した列は
   `bs_current_portion_long_term_debt`・`bs_commercial_paper`・`bs_current_portion_bonds_payable`（既存の列名の
   前に `current_portion_` を付ける）。どの構成要素が欠けたかが後から見える。列の定義が唯一の源という設計制約にそのまま乗る
3. **列の追加 → 取り直し（#918）→ 分子の切り替え（#926）の順**。一度に切り替えると、取り直し前の行（新しい列が
   空欄＝0）と後の行で、同じ年度に2つの定義がエラー無しで混ざる。VIEW は「まだ読んでいない空欄」と
   「科目が無い空欄」を見分けられない
4. **銀行業・保険業だけ D/E を NULL にする**（`database.DE_RATIO_EXCLUDED_INDUSTRIES`）。証券業・その他金融業は残す
   （外すかは #927 で測る）
5. **NULL は1段目で先に効かせる**。歪みを早く止め、3段目の前後比較を「定義の拡大だけ」にする
6. **切り替えの関門は正しさだけで判定し、予測力は記録だけ残す**（#926 の関門は測る前に固定した: 取り直しの完走と
   失敗件数・書類との突き合わせで二重計上が無い・「借入金が空欄で自己資本比率 30% 未満」の社が減る）
7. **`PREPROCESS_VERSION` は上げない**（ADR-0065・0066 と同じ。変わるのはデータで、winsorize→zscore の手順ではない）
8. **IFRS の標準タグは既存の2列へ別名として登録する**: 流動（`BondsAndBorrowingsCLIFRS`・
   `InterestBearingLiabilitiesCLIFRS`・`BorrowingsCLIFRS`）→ `bs_short_term_debt`、非流動（同じ3つの `NCLIFRS`・
   `LongTermDebtNCLIFRS`）→ `bs_long_term_debt`。**IFRS の行だけ2列の意味が広い**（社債と1年内返済分を含む）。
   IFRS の行は新しい3列と `bs_bonds_payable` が空なので、決定2の合計で二重計上にはならない。
   **`bs_bonds_payable` に IFRS のタグは登録しない**（単独の標準タグが無く、合算の行を2列へ入れると二重計上になる）
9. **独自拡張のタグは登録しない**（#852 と同じ。似た名前が内訳や別の範囲を指しうる・日本製鉄の行はリースを含む）。
   これらの社の有利子負債は小さく出る＝**既知の取りこぼし**として残す
10. **`_TAGS_LOSING_TIES` には何も足さない**（22書類に合算と内訳が同じ文脈で並ぶ例が無かった）。#926 の関門2で
    もう一度確かめる

## Consequences

- 1段目の時点では、新しく読む書類から新しい3列と IFRS の連結の借入金が入る。既存の行は #918 の取り直しまで変わらない。
  取り直し後は IFRS の社の D/E が「単体の借入金」から「連結の社債及び借入金」に変わる（分子の式は同じでも
  列の中身が変わる）。#900 の掃除だけを先に当てると IFRS の借入金が空欄＝ D/E 0 に戻るので、取り直しで埋める
- **銀行・保険の D/E と `z_de_ratio` が NULL になる**。2026-10-11 のローカル正本で、通期の 782 行（うち 641 行が
  D/E = 0）が NULL になり、それ以外の業種の `de_ratio` と他の列は1行も変わらないことを、新旧の VIEW を一時 VIEW
  として並べて確かめた。`z_de_ratio` は年度内の平均・標準偏差から銀行・保険の 0 が抜けるので、他の業種の
  28,800 行で値が変わる（最大差 0.776）。同じ年度の中での並び順は変わらない（平均と標準偏差が年度で共通の線形変換）
- **母集団はわずかに動く**（issue の「動かない」は実測で一部違った）。営業利益率を載せる保険会社が毎年 4〜7 社
  （銀行は 2024 年度まで 1 社）あり、`z_de_ratio` を使う factor premia の推定パネルと、`de_ratio` を既定の特徴量に
  含む M-2・M-6（`FIN_BASE_OPTIONS` 全部）からは外れる。年度あたり約 3,900 社の 0.2% 未満。D/E を既定に含まない
  M-1・sector_ols は影響を受けない。推奨の採点（`weighted_score`）は欠けた指標を外して重みを配り直すので、社は消えない
- 業種名を Python の定数と SQL 3 本に写した（`collector_master` の「33業種名をコードへ写さない」の例外）。SQL は
  Python を読めないためで、一致は `tests/test_financial_metrics_with_ttm.py` が照合する。**JPX が業種名を変えると
  黙って効かなくなる**
- 業種は VIEW が `industry` として出す `fr.industry` で判定する。収集直後で業種が空の行は、その晩の業種の
  書き写し（`collector_master._propagate_company_industry`）までは D/E が出る（業種内 Z など他の業種依存の値と同じ遅れ）
- `calc_derived` も同じ条件を持つが、収集の経路は業種を付ける前に呼び、`derived` は保存しないので本番の値には
  効かない（読み手は VIEW）
- `ttm_composite.CARRY_FORWARD_BS_COLUMNS` へは足さない（H1 の欠け方を #926 で測ってから）
