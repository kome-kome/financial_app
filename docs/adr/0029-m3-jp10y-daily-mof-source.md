# M-3 の `dlm_jp10y` を財務省の日次 JGB 金利へ差し替え、実測に従って既定から外す

## Status

accepted（2026-08-07）。Issue #458 の設計決定。**[ADR-0012](0012-m3-dlm-weekly-only-factors.md) の Decision 2 を supersede**（Decision 1／3／4 は有効）。

## Context

ADR-0012 は「M-3 は週次高頻度ファクター専用」と定めたが、`dlm_jp10y` だけは月次 `JP10Y_FRED` を週次差分へ落とす **grandfathered な例外**として残されていた。理由は「日次の日本10年金利ソースが無い」こと（Yahoo `^JGB` は上場廃止で 404・stooq もブロック・#442 で `JP10Y` は `macro_data` に1行も無いと判明）。

この例外の弱さは実測済みだった: **週次差分の 76.89% がゼロ**（#456・961,293 行中 739,100。理論値 1−12/52=0.7692 と一致。日次の `dlm_us10y` は 0.40%）。`_MIN_FACTOR_COVERAGE` は観測頻度を見ず初出日以降の割合だけを見るため coverage=0.9938 で発火せず、自動除外も効かない。

#456 の調査で前提が崩れた。**「日次ソースが無い」のではなく、公的機関の直配信を当たっていなかっただけ**だった——財務省「国債金利情報」が日次で10年物を配信している。実測（2026-08-07 再確認）:

```
全期間版 https://www.mof.go.jp/jgbs/reference/interest_rate/data/jgbcm_all.csv
  1,174,446B / text/csv / cp932 / CRLF / データ 13,270 行（和暦パース失敗 0）
  10年物は 1986-07-05〜2026-07-31 の 9,909 営業日（それ以前は "-"）／**月次更新**

当月版 https://www.mof.go.jp/jgbs/reference/interest_rate/jgbcm.csv
  565B / 当月の営業日のみ（実測 R8.8.3〜8.5）／**日次更新**
```

ライセンスは **PDL1.0**（公共データ利用規約 第1.0版）＝出典表示のみで加工・再配布可。制約が明示されているのは測量法に基づく地図類のみで、数値データは対象外。

## Decision

1. **`MOF_SERIES` コネクタを新設し、`JP10Y_MOF`（日次・1986年〜）を収集する。** `series_code` は月次の `JP10Y_FRED` と対称に置き、コードを見れば収集元が分かるようにする。全期間版は月次更新で当月分を含まないため、**初回は「全期間版 + 当月版」、以降は当月版のみ**を取る（判定は「DB の最古 `trade_date` が要求窓の起点より新しいか」＝`years_back` を伸ばしたときも自然に埋め直しが走る）。

2. **`_DLM_MACRO_MAP["dlm_jp10y"]` を `JP10Y_MOF` へ差し替える。** これで ADR-0012 Decision 2 の例外は解消し、M-3 の全ファクターが日次ソースになる。週次差分のゼロ率は **76.89% → 0.91%**（`load_macro_levels` を通した実測。日次の `dlm_us10y` は 0.59%）。

3. **`lag_days=2`。日次系列では「安全側に大きく取る」ができない。** 基準日 T の値は T+1 に公表される（2026-08-07 JST 01:40 時点で最新が 08-05＝当日公表ではない）。ADR-0028 は低頻度系列について「`lag_days` は理論最大に置く」としたが、日次系列で実配信ラグを超えるシフトを与えると `trade_date` が未来日になり、鮮度ゲートが `ahead_days > 観測周期` を CRITICAL にする。**日次の観測周期は 1 日なので、2 日以上の過大シフトは即 CRITICAL**＝毎晩 exit 2 で自動起票が回り続ける（実測: `lag_days=4` で `max(trade_date)=2026-08-09` ＝ today+2）。したがって**日次系列の `lag_days` の上限は実配信ラグそのもの**になる。

4. **昇格ゲートの実測に従い、`dlm_jp10y` を M-3 の既定から外す**（`_GATE_REJECTED_FEATURES`・選択肢としては残す）。下記の実測どおり、日次化した状態では売り側 spread が補正後 α を通って悪化するため。

## 実測（2026-08-07・`scripts/macro_dlm_feature_bakeoff.py --features dlm_jp10y`）

パネル: 3,982社 / 67期 / 964,466 OOF ペア。base = 既定 21 ファクター（`dlm_jp10y` 抜き）、with_cand = base + `dlm_jp10y`（日次 `JP10Y_MOF`）＝状態次元 22。

| 指標 | base | with_cand | 差 | 95%CI | p | 判定（Bonferroni α=0.025・2検定） |
|---|---|---|---|---|---|---|
| rank-IC | +0.0120 | +0.0115 | −0.0005 | [−0.0011, +0.0001] | 0.076 | ns |
| 売り側 spread | +0.0011 | +0.0010 | −0.0001 | [−0.0002, −0.0000] | **0.023** | **SIG（負方向）** |

OOF サンプル数は 964,466 で不変（非正水準による週落ちは起きない）。elapsed 93.7s → 77.9s。

**情報量が増えたのに成績は下がった。** 月次版のとき（#456・同一パネル）は rank-IC diff −0.0001（p=0.695）／売り側 +0.0000（p=0.206）と 2 検定とも完全に非有意だった。週次差分の 76.89% がゼロ＝「ほぼ何もしない列」だったため、害が出ようがなかったのである。日次化でゼロ率が 0.91% になり**初めて実質的に効くようになった結果、その効きが負だった**。

## Considered Options

- **既定 ON のまま差し替えて完了とする**（却下）: 効果量は極小（売り側 −0.0001・CI 上限 −0.0000）だが、2 指標とも負方向で、うち売り側は ADR-0022 が既定 `mu_source` 選定の主指標に据えたもの。ADR-0028（#454）で「**既定の増減はどちらの向きも補正後 α を通る実測を要する**」と決めた以上、α を通った実測を「効果量が小さいから」で握り潰すと規則が空文化する。
- **月次 `JP10Y_FRED` のまま据え置く**（却下）: 例外が残り続ける。日次ソースが実在すると判明した以上、「取れないから月次」という理由はもう成立しない。なお `JP10Y_FRED` は M-1/M-2/M-6 の `macro_jp10y_fred_zscore`（月次スナップショット）で引き続き使う——月次系列は月次モデルでは正常に機能しており、こちらを触る理由は無い。
- **n_boot を上げて再測する**（却下）: #456 で「**n_boot は検出力に効かない**」（2000→20000 でも p は収束）と実測済み。同じパネルでの再測は結論を変えない。
- **`JP10Y_MOF` の収集自体をやめる**（却下）: 既定から外すのはファクターであって系列ではない。収集を続ければ、レジームが変わったときに `--features dlm_jp10y` で再判定できるし、他モデル（M-1/M-2/M-6 の日次化）や将来のイールドカーブ拡張（2年・5年・20年も同じ CSV の別列にある）の入力にもなる。容量は 9,912 行 ≒ 1MB で無視できる。

## Consequences

- **ADR-0012 Decision 1 が例外なしで成立する**: M-3 の既定 21 ファクターは全て日次ソース。「週次高頻度ファクター専用」という設計に、実装上の例外が1つも無くなった。これが本 ADR の主目的で、rank-IC の改善は目的ではない。
- **M-3 の既定ファクターは 22 → 21**。`dlm_jp10y` は `MACRO_FEATURE_OPTIONS` に残り、UI から手動 ON にできる。`macro_health.critical_series_codes()` は既定から逆引きするため、**`JP10Y_MOF` は critical ではなくなる**（収集は継続・停止しても夜間バッチを落とさない）。
- **`lag_days` の運用に頻度依存の非対称があると分かった**（Decision 3）。低頻度系列は理論最大へ寄せられるが、日次系列は実配信ラグが上限。ADR-0028 の規則をそのまま日次へ適用すると未来日 CRITICAL に当たる。
- **ゼロ差分率は「情報量が乏しい」の指標であって「差し替えれば良くなる」の根拠ではない**、という一般則が実例つきで残った。#456 が「ゼロ率 76.89% という構造的な弱さは残る」と書いたのは正しい観察だったが、それを解消すれば成績が改善するという含みは実測で否定された。
- **収集サーフェス**: `MOF_SERIES` / `parse_mof_jgb_csv` / `fetch_mof_jgb_csv`（`collector_prices.py`）・`SERIES_ANCHOR["MOF_SERIES"]="period_start"`・`macro_health` の系列列挙。`macro_data` スキーマ・GHA ワークフローは**変更不要**（縦持ち・系列汎用）。認証不要のため新規 env var も無い。
- **`lag_days` の再測が宿題として残る**: 初回バックフィル行は `created_at` が潰れているため実配信ラグを実測できない（ADR-0028 規則6）。数週間ぶん日次収集がたまったら、バックフィル日より後に初出した観測だけで実測して引き直す。
- **#442 の決着**: 「`JP10Y` が定義だけ残って1行も蓄積されない」問題は、#442 の定義削除と本 ADR の `JP10Y_MOF` 新設で完結した。
