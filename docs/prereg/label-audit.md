# 事前登録: 採点の物差しの点検（答えが配当を含まない影響・52 週以内の上場廃止で答えが消える影響）

- 事前登録の Issue: https://github.com/kome-kome/financial_app/issues/1154
- 計測道具: `python -m scripts.measure_label_audit`（日中枠 `measure:label-audit`）。
- **凍結**: この文書は main へのマージで凍結する。凍結値は、マーカー行より上（本文）を改行 LF・UTF-8 にそろえた sha256（`scripts/prereg.py`）。
- 実走は日中キューで単独に回す。積むのは計画を承認したセッション（#1154）。

## 1. 問い

モデルの比較（M-6 と M-2 のどちらが上か・売りの候補・上位10社）は、すべて同じ答え＝52 週先の対数リターン `log(c_fut / c_snap)`（`plugins/macro_snapshots.py` の `_build_snapshots_impl`）で採点している。この答えには 2 つの歪みがありうる。

1. **配当を含まない。** 株価は分割調整済み・配当未調整なので、高配当株は実際の儲け（値上がり＋配当）より低く採点される。M-2 は `div_yield` に +1 の単調性の制約（高配当→将来リターン高）を持つので、値上がりだけの採点は M-2 に不利に働きうる。
2. **52 週以内に上場廃止した社が消える。** 答えを作るには 52 行先の終値が要るので、TOB・MBO（プレミアム付きの買い取り）も倒産も学習と採点に入らない（Shumway 1997 の delisting bias）。

測った結果を見てから規則を選ぶと、結論に合わせた規則になる。だから測る前に固定する。

## 2. 対象

- 予測: M-4（3 基底）の共通 (ym, ec) 域の M-1・M-2・M-6 の OOF 予測（`ensemble_base_bakeoff._run_config(keep_common=True)`・M-4 の基底は既定の設定）。参考として本番の設定の M-2（`oof_portfolio_replay.production_predictions`・選択の楽観を含む）を共通域の行だけで並べる。**予測は変えず、答えだけを差し替えて採点する。**
- 値上がりだけの答え `y`: 共通域の答えそのもの。道具は週次終値から `c_snap`・`c_fut` をパネルと同じ規則（`month_end_indices`・`HORIZON_WEEKS`）で引き直し、`log(c_fut / c_snap)` が 1 行でも `y` と食い違えば止まる。値上がりだけの採点の rank-IC と全社の売り側spread の期別系列が M-4 の `base_oof` と食い違っても止まる。
- 配当込みの答え `y_total = log((c_fut + D) / c_snap)`:
  - D は「スナップ日より後に期末を迎える最初の通期」の年間 1 株配当 `dps`（`financial_metrics` VIEW）を、`split_factor × split_dps_lag` で割って今の株数の基準へそろえたもの（VIEW の `div_yield` と同じ補正）。
  - DB に配当の基準日・権利落ち日は無いので期末日を基準日とみなし、52 週の窓に入る配当（期末＋中間）を年間配当 1 回分で近似する。
  - その通期の行が無い、または期末がスナップ日から 400 日より先なら、スナップ日以前に期末を迎えた最新の通期の `dps` で代用する。どちらも無ければ D = 0。`dps` が空なら D = 0。それぞれの件数を出す。
  - D = 0 の行では `y_total` は `y` とビット一致する。
- 消えた行: M-2 / M-6 のレグの構築（`build_snapshots(return_no_future=True)`）で、特徴量の条件をすべて通ったのに答えを作れなかった行。株価の日付で次に分ける。
  - **直近**: スナップ日 + 364 日が「全体の最新週 − 28 日」より後。まだ 52 週たっていない（または収集の遅れ）ので数えない。
  - **途中で終わった**: 系列の最後の足がスナップ日 + 364 日より前（上場廃止・売買停止）。
  - **週の欠け**: それ以外（系列は続くが、週の欠けで 52 行に届かない）。
- 分母の答えのある行も、直近に当たるものは外す（両側をそろえる）。
- 途中で終わった行の理由（**参考・判定に使わない**）: 最後の終値がスナップ時点の 30% 以下なら「倒産の疑い」、そうでなく最後の 4 本の終値の値幅（最大 ÷ 最小 − 1）が 3% 以内なら「TOB/MBO の疑い」、それ以外は「不明」。終値の形だけで分け、出来高は見ない。
- 間引き: なし（`--smoke` なし）。

## 3. 量

- 配当の主審（2 本）: M-6 − M-2（共通域・既定の設定の M-2）の対比較を、(a) rank-IC の期別系列、(b) 全社の売り側spread の期別系列で行う（`model_stats.paired_ic_significance`・定常ブートストラップ・両側 p）。値上がりだけの採点と配当込みの採点の両方で検定する。
- 有意水準: Bonferroni で α = 0.05 / 2 = 0.025（1 検定あたり）。判定は「正に有意」「負に有意」「有意でない」の 3 つ。共通の期が 2 未満で検定が出ないときは「有意でない」とする。
- 配当の副（1 本）: 上位10社超過の期別系列の差 M-6 − M-2 の、両側に共通する期での平均の符号。どちらかの採点で期が無ければ比べない（入れ替わりなしとする）。
- 上場廃止の量: 共通域の test 月での「途中で終わった行 ÷（答えのある行＋途中で終わった行＋週の欠けの行）」。
- 参考（検定しない・判定に使わない）: M-1 と本番の設定の M-2 の行、上位層の売り側spread（M-6 の買いの並びの上位層・`in_layer_short_side`）、precision@10・上位10社の実現順位の平均・lift@10、`y_total − y` の分布（利回り帯別・業種別）、配当の出どころの件数、全月の上場廃止の量、年別・月別の件数、途中で終わった行の理由別の件数とリターンの水準（最後の終値で手仕舞い／倒産の疑いは −100%）と、答えのある行のリターンの水準。

## 4. 判定

- **配当**: (i) 主審 2 本のどちらかで、値上がりだけの採点と配当込みの採点の判定（正に有意／負に有意／有意でない）が入れ替わる、または (ii) 副の符号が入れ替わる、なら「学習の答えを配当込みへ切り替える Issue」を起票する（`PREPROCESS_VERSION` を上げるかを含めて ADR で決める）。どちらも起きなければ記録だけ残し、答えは今のまま。
- **上場廃止**: 上場廃止の量が **1%** を超えたら（ユーザー判断・2026-11-09）、答えの作り方を設計し直す Issue を起票する（消えた社を採点に足すには、答えの無い行にも予測を出す経路が要る。その設計を含む）。1% 以下なら記録だけ残す。分母が 0 なら判定しない。
- 判定は計測道具が `prereg_decision` に機械的に出す（`measure_label_audit.dividend_decision`・`delisting_decision`）。読み手は手で判定し直さない。
- 道具が非 0 で止まった（凍結値の不一致・答えの照合の不一致・`base_oof` との不一致・構築を捕まえられない）ときは判定しない。
- どちらの Issue も、起票の時点では本番を変えない。切り替えは別の PR にする。

1. 日中キューに `measure:label-audit` を積む。計測道具は `--prereg` と `--prereg-sha`（追記節の凍結値）を必須にし、本文が凍結値と一致しなければ終了コード 2 で止まる。

3. 判定に従って Issue を起票する。どちらも「記録だけ」なら結果を記録して #1154 を閉じる。#1152・#1155・#1157 は、この結論の答えで採点する。
