# 事前登録: 買いの主役（M-6）と M-2 の差を、OOF の期が増えるたびに点検する規則

- 事前登録の Issue: https://github.com/kome-kome/financial_app/issues/1225
- 道具: 計測は `python -m scripts.measure_delisting_redesign`（日中枠 `measure:delisting-redesign`）の結果の `series`。読むのは `python -m scripts.buy_lead_watch`（結果の JSON を読むだけで、DB を触らない）。
- **凍結**: この文書は main へのマージで凍結する。凍結値は、マーカー行より上（本文）を改行 LF・UTF-8 にそろえた sha256（`scripts/prereg.py`）。
- **位置づけ**: 見張りの規則。条件に当たっても本番は切り替えない。買いの主役を見直す Issue を起票するだけ。

## 1. 問い

買いの主役は M-6（`macro_enet`）だが、直近の期だけを見ると M-2（`macro_gbdt`）のほうが良い。

- 全 19 期（2021-02〜2025-08）: rank-IC は M-6 +0.2017・M-2 +0.1581。差 +0.0436 は p = 0.099 で有意でない。
- 2024 年以降の 7 期: rank-IC は M-2 +0.2298・M-6 +0.1925。差（M-6 − M-2）−0.0374 は p = 0.001。上位 10 社の超過の差は −0.0696。

（`docs/prereg/delisting-redesign.md` の追記節・2026-11-13 の計測。）

7 期は少なく、今は結論を出せない。けれども、期が増えても誰も見直さなければ、前提が変わったことに気付けない。そこで、どの量が何回続いたら見直しを始めるかを、次の期が出る前に固定する。

## 2. 対象

- 対: M-6（`macro_enet`）− M-2（`macro_gbdt`・M-4 の基底＝既定の設定）。
- 母集団: M-4 の 3 基底に共通する (月, 社)。答えのある行だけ（今の採点。上場廃止した行は足さない・ADR-0075）。
- 期: `measure_delisting_redesign` の test 月（3 か月おき）。
- 窓は 2 つ。
  - 全期: すべての test 月。
  - 直近 8 期: 最後の test 月から数えて 8 期。
- 本番の設定の M-2（M-2\*）は判定に使わない。成績を見て選んだ設定で、選択の楽観を含むため。#1155 の結果（`scripts/.cache/selection_optimism.json` の期ごとの値）が出た後に、同じ 2 つの窓の表を参考として追記節に並べる。

## 3. 量

- (a) rank-IC の差（M-6 − M-2）の期別系列の平均。両側に共通する期で対にし、`model_stats.paired_ic_significance`（定常ブートストラップ・両側 p・反復数とブロック長と seed は既定）で検定する。
- (b) 上位 10 社の超過の差（M-6 − M-2）の期別系列の平均。1 期あたりのぶれが大きいので検定せず、符号だけを見る。
- 有意水準: α = 0.05 / 2 = 0.025（窓が 2 つ）。
- (a)・(b) とも 2 つの窓で出す。判定に使うのは直近 8 期だけで、全期は並べるだけ。

## 4. 判定

- **当たり**: 直近 8 期で、(a) の平均が負で p < 0.025、**かつ** (b) の平均が負。
- **数える点検**: 最後の test 月が 2025-08 より後の点検だけ。凍結の時点の 19 期（最後の test 月 2025-08）は、この規則を作るきっかけになった数字なので、「基準の回」として記録するだけで数えない。最後の test 月が同じ点検は、何度読んでも 1 回。
- **動く条件**: 数える点検で **2 回続けて**当たりなら、買いの主役を見直す Issue を起票する。自動では切り替えない。見直しの中身（M-2 を主役にする、2 本の比重を変える、など）はその Issue で決める。
- 当たりでない「数える点検」が入ったら、連続は 0 に戻る。
- 判定しない場合: 間引いた動作確認（`--smoke`）の出力、`series` が無い出力、期数が 8 に満たない、M-6 と M-2 の期がそろわない。
- 当てはめは `buy_lead_watch` が機械的に行う。読み手は手で判定し直さない。

## 5. 手順

1. 新しい test 月が採点できるようになったら（52 週先の株価がそろう 3・6・9・12 月の初め以降が目安）、`measure:delisting-redesign` を日中キューへ積み、単独で回す。
2. `python -m scripts.buy_lead_watch --prereg docs/prereg/buy-lead-watch.md --prereg-sha <凍結値>` を実行し、出力の「点検の記録」の 1 行を、追記節の表に足す。
3. 動く条件に当たったら Issue を起票する。
4. 次の点検日を書いた Issue を開けておく（点検が忘れられないようにする）。

## 6. 凍結し直す条件

最初の「数える点検」（最後の test 月が 2025-11 以降）を読む前に限り、本文と凍結値を同じ PR で変えてよい。読んだ後に対象・量・判定を変えるなら、新しい ADR で覆す。計測道具の採点の手続き（共通域・基底の設定）が変わったときは、そのことを点検の記録に書き、連続を 0 から数え直す。
