# 事前登録: 本番の画面が出した予測（月次の写し）を、写した後に出た答えで採点し、M-6 と M-2 を上位10社で比べる

- 事前登録の Issue: https://github.com/kome-kome/financial_app/issues/1157
- 関連: #1005（写し）・#1155（OOF での公平な比較）・#1195（上場廃止した社の扱い）・ADR-0070・ADR-0073
- 計測道具: `python -m scripts.measure_live_oos`（日中枠 `measure:live-oos`）。
- **凍結**: この文書は main へのマージで凍結する。凍結値は、マーカー行より上（本文）を改行 LF・UTF-8 にそろえた sha256（`scripts/prereg.py`）。
- 実走は日中キューで単独に回す。積むのは #1157 を再開したセッション（§5 の時期）。

## 1. 問い

OOF の比較は、どれも設定を選んだ期と同じ過去の期で採点している。探索した M-2 の本番の設定には選択の楽観が残る（#1155）。一方、本番の画面の予測は 2026-10 から月に 1 回、その時点の値のまま `prediction_snapshots` に写されている（#1005）。写した**後**に出た答えで採点すれば、設定を選んだ期と採点の期が重ならない。本番の画面が実際に出した予測で、上位10社を買う運用（ADR-0070）に、M-6 の μ̂ と M-2（写した時点の本番の設定）の μ̂ のどちらが良かったかを比べる。答えが出てから物差しや比べ方を選ぶと、効いて見える物差しを選べてしまう（ADR-0045・ADR-0050）。そこで、最初の答え（13 週先は 2027-01・52 週先は 2027-10）が出る前に固定する。

## 2. 対象

- 予測: `prediction_snapshots` の値。μ̂ の源は `mu`、`sector_ols` は `gap_ratio`（`prediction_snapshots.value_column`）。主審は `macro_enet`（M-6）と `macro_gbdt`（M-2・写した時点の本番の設定＝探索の周回が反映した設定）。値が有限でない行は使わない。
- 写し: 2026-10 以降の全ての写した日（`snapshot_date`）。ある写した日にある源の値が 1 つも無いとき（#1005 の初回の `macro_risk_return` のように、μ̂ が全部空で写された源）は、その源のその写しだけを外し、他の源は数える。過去の写しは書き換えない。
- 答え: 値上がりだけの対数リターン（ADR-0073 決定 3）。社ごとに週次足（`stock_price_weekly.close_last`・`load_weekly_prices_chunked`）を日付順に並べ、**写した日以前の最後の足**を起点に、その 52 本先（13 本先）の足の終値との `log(c_fut / c_start)` を取る。足の本数で数えるのは、学習の答え（`plugins/macro_snapshots.py` の `closes[snap_idx + HORIZON_WEEKS]`）と同じ規則。起点の足が写した日より 28 日以上前の社は答えを作らない（写した時点で取引の無い社）。
  - 起点を写した日にそろえるので、同じ写しの同じ社は、どの源でも同じ答えになる。予測が使ったデータの時点（`data_asof`）は源ごとに違い、月次で回るモデルは写した日より古い。その差は「画面を見て買った時点からの成績」に含める（運用と同じ）。
- 成熟: 写した日 + 52 週（13 週）が、計測した日（JST）と全社の最新の週次足の日付の両方以前のとき、その写しの答えが出たとみなす。成熟していない写しは採点に入れない。
- 上場廃止した社（主審）: 成熟した写しで 52 本先の足が無い社は、主審に入れない（今の本番の学習・採点と同じ・ADR-0074）。
- 比べる行（主審）: 成熟した写しごとに、M-6 と M-2 の両方に値があり、答えもある社（共通域）。超過の基準（共通域の答えの平均）が両者で同じになる。並びはどちらも μ̂ の順。
- 間引き: なし（`--smoke` なし）。

## 3. 量

- 主審（1 本）: 52 週の答えでの上位10社超過（`oof_backtest` の `top_k_excess_return_by_period["10"]`）の写し別系列の対比較 M-6 − M-2。
- 判定に使う写し: 両方の系列に値がある写しを日付順に並べた**最初の 36 本だけ**。37 本目以降は参考。36 本そろうまでは検定しない。
- 検定: `model_stats.paired_ic_significance`（定常ブートストラップ・両側 p）を、平均ブロック長 12（`LABEL_HORIZON_MONTHS`）で使う。月次の写しの 52 週の答えは、隣の 11 か月の答えと期間が重なるため。反復回数と種は `model_stats` の既定。
- 有意水準: α = 0.05（主審 1 本なので補正なし・ADR-0063）。判定は「正に有意」「負に有意」「有意でない」。
- 参考（検定しない・判定に使わない）:
  - 各源（全ての源・gap を含む）自身の母集団での、上位10社超過・上位10社の実現順位の平均・precision@10・lift@10・rank-IC
  - 共通域での M-6・M-2 の同じ指標
  - 売り: 1 つ前の写しで M-6 の μ̂ が上位 1/5 だった社（上位層）の中で、各 μ̂ の源の下位 1/5 を売ったときの上位層の売り側spread・precision・誤売りの損（`in_layer_short_side`）。源ごとに単独で測り、M-6・M-2 の対は両方がそろう社で測る。写しに源が足されたら（例: 売り専用の S2）、足された月から並ぶ
  - 上場廃止した社（52 本先の足が無く、系列の最後の足が起点 + 52 週より前で、起点 + 52 週が全社の最新の足より 28 日以上前の社）を、最後の終値で手仕舞った答えで足した版（#1195 の案 1 と同じ形）
  - 起点を `data_asof` にした版（μ̂ の源だけ。gap の `data_asof` は決算期末なので測らない。`data_asof` が空の行は答えを作らない＝今の `macro_risk_return` の写しは as-of を持たないので入らない）
  - 13 週の答えでの上の全て（中間点検＝道具の点検）
  - 源ごとの写しの件数、成熟した写しの本数、源ごとの答えの内訳（答えあり・上場廃止・足の欠け・収集の遅れ・起点なし）

## 4. 判定

- 共通の成熟した写しが 36 本未満 → **`accumulating`**: 判定しない。数字は参考。
- 主審が正に有意 → **`m6_better`**: 本番の予測で M-6 が上だった。
- 主審が負に有意 → **`m2_better`**: 本番の予測で M-2 が上だった。買いの主を M-2 に戻すかを利用者が判断する。
- それ以外 → **`no_difference`**: 差なし。
- 判定は計測道具が `prereg_decision` に機械的に出す（`measure_live_oos.decide`）。最初の 36 本だけを使うので、36 本そろった後はいつ回しても同じ判定になる。読み手は手で判定し直さない。
- 道具が非 0 で止まった（凍結値の不一致・写しか週次株価が空）ときは判定しない。
- どの判定でも本番は変えない。買いの主を変えるなら別の Issue と PR にする。

## 5. 手順

1. 13 週の中間点検: 2027-01-25 以降に、日中キューへ `measure:live-oos` を単独で積む。道具の点検（写しが読める・答えが作れる・件数が妥当）で、判定には使わない。計測道具は `--prereg` と `--prereg-sha`（追記節の凍結値）を必須にし、本文が凍結値と一致しなければ終了コード 2 で止まる。
2. 52 週の参考: 2027-10 下旬から、毎年 10 月下旬に 1 回積む。
3. 判定: 共通の成熟した写しが 36 本そろう見込みの 2030-09 下旬以降に積み、`prereg_decision` を読む。
4. 各回の出力（`scripts/.cache/live_oos.json`）の主審・判定・参考を、追記節の「結果」に回ごとに書き写す。
5. 判定が出たら #1157 に記録して閉じる。`m2_better` なら、買いの主を見直す Issue を起票してから閉じる。

## 6. 凍結し直す条件

答えが 1 つでも採点に入った実走（成熟した写しが 1 本以上あった実走。最初は 2027-01 の中間点検）より前に限り、本文と凍結値を同じ PR で変えてよい。成熟した写しが 0 本の実走は、答えを見ていないので回したうちに数えない。#1195 の結論で採点の答えに上場廃止した社を足すと決まったら、この期限の前に §2 の主審の答えを差し替える。回した後に対象・量・判定を変えるなら、新しい ADR で覆す。
