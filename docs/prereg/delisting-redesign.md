# 事前登録: 52 週以内に上場廃止した行を採点に足すと、M-6 と M-2 の比較の判定が変わるか

- 事前登録の Issue: https://github.com/kome-kome/financial_app/issues/1197
- 親: #1195（答えの作り直し）。方針は ADR-0074。前の計測は `docs/prereg/label-audit.md`（#1154）。
- 計測道具: `python -m scripts.measure_delisting_redesign`（日中枠 `measure:delisting-redesign`）。
- **凍結**: この文書は main へのマージで凍結する。凍結値は、マーカー行より上（本文）を改行 LF・UTF-8 にそろえた sha256（`scripts/prereg.py`）。
- 実走は日中キューで単独に回す。積むのは計画を承認したセッション（#1197）。

## 1. 問い

モデルの比較は「52 週先の終値がある行」だけで採点している。途中で上場廃止した社の行（特徴量はそろうのに 52 週先の終値が無い行）は、学習にも採点にも入らない。#1154 の計測では、廃止社の株価がそろう 2025 年の test 月でその割合が 2.87% あり、多くは TOB の当たり、一部は倒産の疑いだった（ADR-0074）。

この行を採点に足すと、M-6 と M-2 の比較の判定が変わるかを測る。**学習は変えない**（採点だけを変える）。測った結果を見てから規則を選ぶと、結論に合わせた規則になる。だから測る前に固定する。

## 2. 対象

- 予測: M-4（3 基底）の共通 (ym, ec) 域の M-2・M-6 の OOF 予測（`ensemble_base_bakeoff._run_config(keep_common=True)`・M-4 の基底は既定の設定）。#1154 と同じ域・同じ予測。
- 足す行（消えた行）: M-2 / M-6 のレグの構築（`build_snapshots(return_no_future=True, return_no_future_rows=True)`）で、特徴量の条件をすべて通ったのに答えを作れなかった行のうち、**途中で終わった行**だけ。`measure_label_audit.classify_no_future` が `ended` と分けた行（系列の最後の足がスナップ日 + 364 日より前で、かつスナップ日 + 364 日が全体の最新週 − 28 日以前）。直近の行・週の欠けの行は足さない。
- 消えた行の予想: 各 fold で、M-2（XGBoost）と M-6（ElasticNet）の学習済みモデルに、その fold の test 月の消えた行も予測させる（学習データには入れない）。M-6 には答えのある行と同じ規模の中立化を掛ける: その月の答えのある行の予想で求めた傾き b と x̄（`size_slope`）を使い、`μ̂' = μ̂ − b(x − x̄)`（x はその行の log 時価総額。無ければ補正しない）。足すのは、M-2 と M-6 の両方に予想が出た行だけ。
- 消えた行の答え（手仕舞い）: `log(最後の終値 / スナップ時の終値)`。最後の終値は、スナップ以降の正の終値のうち最後のもの。出せない行は足さない（件数を出す）。
- 期: 共通域の test 月 19 期（#1154 と同じ）。2023 年以前の test 月には消えた行が無い（#1188）ので、その月は 2 つの採点で同じ値になる。
- 間引き: なし（`--smoke` なし）。

## 3. 量

- 主審（2 本）: M-6 − M-2 の対比較を、(a) rank-IC の期別系列、(b) 全社の売り側spread の期別系列で行う（`model_stats.paired_ic_significance`・定常ブートストラップ・両側 p）。「答えのある行だけ」の採点と「消えた行を足した」採点の両方で検定する。
- 有意水準: Bonferroni で α = 0.05 / 2 = 0.025（1 検定あたり）。判定は「正に有意」「負に有意」「有意でない」の 3 つ。共通の期が 2 未満で検定が出ないときは「有意でない」とする。
- 副（1 本）: 上位10社超過の期別系列の差 M-6 − M-2 の、両方の採点に共通する期での平均の符号。どちらかの採点で期が無ければ比べない（入れ替わりなしとする）。
- 参考（検定しない・判定に使わない）: 倒産の疑い（`classify_no_future` の `bankruptcy_suspect`）の行の答えを log(0.01)（−99%）にした版の同じ量、2024 年以降の test 月だけの値、足した行数（月別・理由別）、モデルごとの rank-IC・全社の売り側spread・上位10社超過・precision@10・上位10社の実現順位の平均・lift@10。

## 4. 判定

- 主審 2 本のどちらかで「答えのある行だけ」と「消えた行を足した」の判定（正に有意／負に有意／有意でない）が入れ替わる、または副の符号が入れ替わるなら **propose_include**: 「比較の採点に消えた行を足す Issue」を起票する（学習にも足すか・どの比較から適用するかを含めて #1195 で決める）。
- どちらも起きなければ **keep**: 記録だけ残し、採点は今のまま。#1195 を閉じる。
- 判定は計測道具が `prereg_decision` に機械的に出す（`measure_delisting_redesign.include_decision`）。読み手は手で判定し直さない。
- 道具が非 0 で止まった（凍結値の不一致・答えの照合の不一致・`base_oof` との不一致・M-6 の中立化を再現できない・消えた行の予想の件数が合わない）ときは判定しない。
- 起票の時点では本番を変えない。

## 5. 手順

1. 日中キューに `measure:delisting-redesign` を積む。計測道具は `--prereg` と `--prereg-sha`（追記節の凍結値）を必須にし、本文が凍結値と一致しなければ終了コード 2 で止まる。
2. 出力（`scripts/.cache/delisting_redesign.json`）の主審・副・判定・参考の値を、追記節の「結果」に書き写す。
3. 判定に従い、propose_include なら Issue を起票し、keep なら記録して #1195 を閉じる。

## 6. 凍結し直す条件

計測道具を一度も回していない間に限り、本文と凍結値を同じ PR で変えてよい（間引いた動作確認 `--smoke` は回したうちに数えない）。回した後に対象・量・判定を変えるなら、新しい ADR で覆す。
