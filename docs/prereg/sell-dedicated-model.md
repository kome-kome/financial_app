# 事前登録: 売り専用に学習した候補（下位に入る確率）を、売りの μ̂（M-6）と比べる

- 事前登録の Issue: https://github.com/kome-kome/financial_app/issues/1152
- 計測道具: `python -m scripts.sell_mu_source_bakeoff --sell-candidates`（日中枠 `measure:sell-dedicated`）。
- **凍結**: この文書は main へのマージで凍結する。凍結値は、マーカー行より上（本文）を改行 LF・UTF-8 にそろえた sha256（`scripts/prereg.py`）。
- 実走は日中キューで単独に回す。積むのは計画を承認したセッション（#1152）。

## 1. 問い

売り候補ランキング（`sell_ranking`）は、M-6（`macro_enet`）の μ̂ を昇順に並べ、保有の下位 1/5 を SELL にしている（ADR-0071）。M-6 は 52 週先リターンの平均を二乗誤差で当てるように学習しており、並びの下側の当たり外れを特に重く扱ってはいない。当てる答えを「その月の下位 1/5 に入るか」に替えた候補（S1）は、売りとして M-6 の μ̂ より当たるか。文献ではアノマリーの利益は売り側に偏る（Stambaugh, Yu & Yuan 2012）。一方で今の手法は強く（全社の売り側spread +0.1097・#1058）、期は 17〜19 しかないので、最もありそうな結果は「差なし」。だから測る前に規則を固定する。

## 2. 対象

- 候補: **S1 だけ**。当てる答えは「52 週先リターンが、その月の学習行の下位 1/5 に入るか」（月内の昇順の先頭 m // 5 行を 1。`oof_backtest` の最下位分位と同じ切り方）。学習器は L1+L2 のロジスティック回帰（`LogisticRegressionCV`・saga・random_state 42）。C は 1e-4〜1e4 の対数等間隔 10 点、l1_ratio は本番の M-6 と同じ候補。内側 CV の区切り方と分割数も本番の M-6 と同じ（`macro_enet._INNER_CV`・`_CV_SPLITS`）で、対数損失が最小の組を選ぶ。予測は −P(下位)（`plugins.model_candidates.make_logistic_bottom_fit_predict`）。
- 分位回帰の候補（S2）は外した。本番の大きさ（約 20 万行）では 1 回の学習が行数の 2 乗に近く伸び（合成データ 72 列で 2 万行 11.7 秒・6 万行 90.4 秒）、日中枠に収まらないため（ユーザー判断・2026-11-09）。
- 分母: 本番の売りの μ̂ の出どころ M-6（`sell_ranking.MU_SOURCE`）。
- 両側で同じもの: M-4 の中の M-6 のレグ（`MacroEnsemblePlugin._m6_cv`）が受け取るパネル・月（特徴量は本番の M-6 の既定。#1145 の後は財務 19 列）、外側の walk-forward（同じ fold・embargo）、前処理（学習 fold だけで fit する winsorize → zscore）、OOF への規模の中立化（`macro_enet._SIZE_NEUTRAL`）。違うのは当てる答えと学習器だけ。
- 比べる域: M-4（3 基底）の共通 (ym, ec) 域。共通域の行が候補に無い、または実現リターンが食い違うときは道具が止まる。
- 間引き: なし（`--smoke` なし）。

## 3. 量

- 主審（2 本）:
  - (a) 上位層の売り側spread の期別系列（`in_layer_short_side`）。上位層は 1 つ前の test 期に **M-6 の買いの並び（μ̂）** で上位 20% だった社のうち、その期にも予測がある社（ユーザー判断・2026-11-09）。
  - (b) 全社の売り側spread の期別系列（`whole_universe_short_side`・ADR-0069 の売りの主審）。
- 差: S1 − M-6。両側に共通する期だけで対にする（`model_stats.paired_ic_significance`・定常ブートストラップ・**両側 p**）。
- 有意水準: Bonferroni で α = 0.05 / (1 候補 × 2 指標) = 0.025（`sell_mu_source_bakeoff.sell_alpha`）。
- 参考（検定しない・判定に使わない）: M-2・M-1 の買いの並びで作った上位層の (a)、当たり率、各売りのキーを買いの並びとして読んだ rank-IC、選ばれた C・l1_ratio・非ゼロ係数の数・収束しなかった警告の数、両側の期数。

## 4. 判定

- **採用**: (a) の差が正で p < 0.025、**かつ** (b) の差が「負で p < 0.025」ではない（全社の売り側spread は拒否権）。
- **据え置き**: それ以外。`sell_ranking` は M-6 の μ̂ のまま。
- 検定が出ない指標（共通の期が 2 未満）は有意でないものとして扱う（(a) が出なければ据え置き、(b) が出なければ拒否権は発動しない）。
- 判定は計測道具が `prereg_decision` に機械的に出す（`sell_mu_source_bakeoff.sell_dedicated_decision`）。読み手は手で判定し直さない。
- 道具が非 0 で止まった（凍結値の不一致・共通域の行の欠け・実現リターンの食い違い・全社の再計算が M-4 と合わない）ときは判定しない。
- 採用でも、本番の切り替えは別の PR にする（ADR-0071 を覆す新しい ADR・producer への昇格・登録表）。

## 5. 手順

1. 日中キューに `measure:sell-dedicated` を積む。計測道具は `--prereg` と `--prereg-sha`（追記節の凍結値）を必須にし、本文が凍結値と一致しなければ終了コード 2 で止まる。
2. 出力（`scripts/.cache/sell_dedicated.json`）の主審の 2 本・判定・参考の値を、追記節の「結果」に書き写す。
3. 採用なら本番を切り替える別の Issue を起票する。据え置きなら結果を記録して #1152 を閉じる。

## 6. 凍結し直す条件

計測道具を一度も回していない間に限り、本文と凍結値を同じ PR で変えてよい（間引いた動作確認 `--smoke` は回したうちに数えない）。回した後に対象・量・判定を変えるなら、新しい ADR で覆す。
