# 事前登録: M-6 と本番の設定の M-2 を上位10社で公平に比べる（探索の選び方を時間順にやり直して選択の楽観を抜く）

- 事前登録の Issue: https://github.com/kome-kome/financial_app/issues/1155
- 計測道具: `python -m scripts.measure_selection_optimism`（日中枠 `measure:selection-optimism`）。
- **凍結**: この文書は main へのマージで凍結する。凍結値は、マーカー行より上（本文）を改行 LF・UTF-8 にそろえた sha256（`scripts/prereg.py`）。
- 実走は日中キューで単独に回す。**12 月の探索の周回が新しい財務（#1150・#1153 の後）で本番の設定を選び直して反映した後**に積む（参考の「本番の設定」の行がそろうため）。積むのは #1155 を再開したセッション。

## 1. 問い

M-6 を M-2 より上とした判断（ADR-0021・ADR-0022）は、物差しが rank-IC と全社の売り側spread で、相手は既定の設定の M-2 だった。利用者の運用は「画面の上位10社を買う」（ADR-0070）で、画面の M-2 は探索で選んだ本番の設定である。本番の設定の成績をそのまま比べると、採点と同じ期のデータで 150 候補から選んだ分だけ良く見える（選択の楽観・ADR-0070 が選択肢 9 を却下した理由）。各時点でその時点までに答えが出ていた期だけを使って選び直した M-2（時間順に選んだ M-2）と M-6 を、同じ社・同じ期の上位10社で比べる。結果を見てから規則を選ぶと結論に合わせた規則になるので、測る前に固定する。

## 2. 対象

- 共通域: M-4（3 基底）の共通 (ym, ec) 域と test 月（`ensemble_base_bakeoff._run_config(keep_common=True)`）。
- **M-6**: 共通域の M-6 の予測（規模の中立化込み）。
- **本番の設定の M-2（M-2\*・参考の上限）**: `plugin_tuned_params` を比較画面と同じ射影で写した設定の単体の M-2（`oof_portfolio_replay.production_predictions`）。test 月を共通域にそろえる。採点と同じ期で選んだ設定＝選択の楽観を含む。
- **時間順に選んだ M-2**:
  - 候補は本番の探索と同じ固定の候補集合（`plugins.tuning.candidate_pool`。引数は `run_daytime.JOBS["tune:macro_gbdt"]` の argv＝random・150 件・種 0、確かめ直す段は上位 5 件・5 種）。全候補を同じパネルで 1 回ずつ、test 月を共通域にそろえて単体の M-2 で回す（`oof_portfolio_replay.predictions_with_params`）。
  - 各 test 期 t で使える期は、答えが t の 12 か月前までに出そろった期（`months_between(p, t) >= 12`）だけ。使える期が 2 期に満たない t は選べないので、**比較から外す**（既定の設定で埋めない。埋めると上位10社の弱い既定の M-2 が混ざる）。
  - 選び方は本番（ADR-0070 決定 2・`_confirm_by_seeds`）と同じ規則を、使える期に限って当てる。
    1. 種 42 の rank-IC の平均（使える期だけ）の上位 5 件と、1 つ前の期に選んだ設定を決勝候補にする（本番の champion にあたる）。
    2. 決勝候補を種 42〜46 で測り直して種平均し（全種にある期だけ）、種平均の rank-IC の降順に並べて `plugins.tuning._two_stage_select` で選ぶ（1 段目は両側 α 0.10・2 段目は上位10社超過の平均最大）。
    3. 選べなければ種平均の rank-IC 最大。種のどれかで失敗した候補は外す。
  - 種の測り直しは、全期の決勝候補の和集合を種ごとの巡でまとめて回す。締切（日中枠の予算 − 15 分）に入らない巡からは止め、回し切った種だけで平均する（本番と同じ畳み方）。
  - 各 t の予測は、t で選んだ設定の種 42 の予測（本番の μ̂ と同じ種）。
- 答え: 計測の時点のパネルの答え（52 週先の対数リターン。#1154 の結論で答えが切り替わっていればそれに従う）。
- 比べる行: 選べた期の、3 つの予測と答えがすべてそろう共通域の行。並びはどれも μ̂ の順。
- 間引き: なし（`--smoke` なし）。

## 3. 量

- 主審（2 本）: 上位10社超過（`oof_backtest` の `top_k_excess_return_by_period["10"]`）の期別系列の対比較。
  - (a) M-6 − 本番の設定の M-2
  - (b) M-6 − 時間順に選んだ M-2
  - 両側に共通する期だけで対にする（`model_stats.paired_ic_significance`・定常ブートストラップ・両側 p）。
- 有意水準: Bonferroni で α = 0.05 / 2 = 0.025（1 検定あたり）。判定は「正に有意」「負に有意」「有意でない」。共通の期が 2 未満で検定が出ないときは「有意でない」。
- 参考（検定しない・判定に使わない）: 上位10社の実現順位の平均、precision@10、lift@10、rank-IC、全社の売り側spread、μ̂ の順の OOF 運用再現（K=10・k=2・売りは M-6 の μ̂・10bp）、各期の選択（決勝候補・同点の集合・選び方）、回し切った種、全候補の期別系列。

## 4. 判定

- (b) が負に有意（時間順に選んだ M-2 が上）で (a) が正に有意でない → **`consider_m2`**: 買いの主を M-2 に戻すかを利用者が判断する。
- (a) が正に有意（楽観込みの M-2 より M-6 が上）で (b) が負に有意でない → **`m6_confirmed`**: M-6 の優位は確か。
- (a) が正に有意かつ (b) が負に有意 → **`conflict`**: 理屈の上では起きない組み合わせ（楽観込みの M-2 は時間順の M-2 以上のはず）。道具の不具合を疑い、判定しない。
- それ以外 → **`no_difference`**: 差なし。両方の画面を使ってよい。
- 判定は計測道具が `prereg_decision` に機械的に出す（`measure_selection_optimism.decide`）。読み手は手で判定し直さない。
- 道具が非 0 で止まった（凍結値の不一致・150 件を締切までに回し切れない・本番の設定の M-2 が出せない・選べた期が無い）ときは判定しない。
- どの判定でも本番は変えない。買いの主を変えるなら別の Issue と PR にする。

## 5. 手順

1. 12 月の探索の周回の反映（`app_settings` の `tuning_cycle:macro_gbdt` の `last_finished_at` が 2026-12 以降・`persisted=True`）を確かめてから、日中キューに `measure:selection-optimism` を単独で積む。計測道具は `--prereg` と `--prereg-sha`（追記節の凍結値）を必須にし、本文が凍結値と一致しなければ終了コード 2 で止まる。
2. 出力（`scripts/.cache/selection_optimism.json`）の主審 2 本・判定・参考の値を、追記節の「結果」に書き写す。
3. `consider_m2` なら利用者の判断を #1155 に記録してから閉じる。それ以外は結果を記録して #1155 を閉じる。

## 6. 凍結し直す条件

計測道具を一度も回していない間に限り、本文と凍結値を同じ PR で変えてよい（間引いた動作確認 `--smoke` は回したうちに数えない）。回した後に対象・量・判定を変えるなら、新しい ADR で覆す。
